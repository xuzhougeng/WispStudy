## Author names

Author names are kept as the source wrote them, `A; B; C`, in three forms: `Zhang, Tian-Qi` (PubMed, Crossref, BibTeX), `Tian-Qi Zhang` (arXiv, Zotero) and, in libraries from before, `Zhang TQ` (Europe PMC, the family name first and initials after it). `model::author_names` is the one reader that says which word is the family name, for a whole list at once (a name ending in one capital is the third form, one ending in two or three when most of the list is written so); `Paper::citation`, the citation keys and reference list of `cite`, and the BibTeX of `export` all go through it, and a new reader of names does too. `lookup::europepmc_hit` now stores such names with their comma (`model::family_first`, or the name's own parts when the record has them). A key already cited stays as `cite_keys` has it.

Where in its journal a paper is: `Paper::volume`, `issue` and `pages`, three strings (columns added by `store::add_columns`; an older build leaves them as they are when it saves a paper). Every reader fills them: Crossref (`volume`, `issue`, `page`, else `article-number`), Europe PMC (`journalInfo`, `pageInfo`), PubMed (`JournalIssue`, `Pagination`), BibTeX (`volume`, `number`, `pages`), RIS (`VL`, `IS`, `SP` / `EP`), Zotero (the fields `volume`, `issue`, `pages`), and 按题目补全 offers them like any other field. `model::clean_pages` is the one shape pages are kept in (`357-362`: a plain hyphen, the last page in full); `lookup::merge_lookup` takes a second source's three only when it names the same journal or none. They are written by `csl::entry`, `cite::reference` (through `Paper::placed`, `585(7825), 357–362`) and the BibTeX and CSV of `export`.

## Note saving and export (`notes.rs`)

Note saving/export: core's notes.rs prepares editable Markdown drafts from personal notes and selected conversation questions, copies images for local export, and keeps publication metadata at the existing year precision. Desktop src/notes.rs and the tools list_note_sources / prepare_note / export_note / save_note_to_notion share that document. net's notes.rs publishes through the existing mcp.rs client and OAuth (no separate client/settings DB). Per-library note_saves reserves writes before sending; an OS lock prevents reconciliation during an active write. Uncertain writes stop and require explicit human reconciliation via resolve_note_save. The generic MCP client never replays tools/call after transport errors. Cache saved links in Library::reload, never query the DB from render. Desktop saving uses a compact destination picker with optional read-only preview; source choices only appear for chat, refresh the document automatically, and preserve edited titles. Debug startup exportnote opens personal-note saving; exportnote:paper or exportnote:library selects chat sources; notedestination:local, notepreview and notepick:<index> exercise the dialog without writing. Live test: cargo run -p wisp_net --example note_smoke -- <explicitly approved parent page ID>, with an isolated WISP_STUDY_HOME already authorized for Notion; it creates synthetic content and leaves its page for inspection.

## Word files (`docx.rs`)

`docx.rs` reads and writes Word files for 写作, by hand (a zip reader that keeps unchanged entries as packed, an XML tokenizer that keeps what it does not change as written): a tree parser that writes its tree again would not promise an untouched paragraph back to the byte. `read` gives the body's paragraphs that say something (text of `w:t`, a tab or line break as a space; struck text not counted, inserted text counted; no table of contents, nothing inside tables), each heading's level (its style's name `heading N`, which Word keeps in English, or an outline level) and the comments with the words their ranges cover. `rewrite` takes the paragraphs the manuscript now has (`Wanted`: text, role, comments) and writes the same file saying them: `align` matches old and new paragraphs (equal ones first, then those alike by `likeness`, as many leftovers as came changed in place, the rest taken out and put in), an unchanged paragraph is the original XML, a changed one is changed inside its runs (`Para::edited`: word-level `ops`, what stays keeps its run, what comes joins the run of the text before it; `Options::track` writes `w:ins` / `w:del` with ids after the file's largest), a new one is set like the nearest paragraph of its kind, and one taken out that holds a section break or a picture keeps those. Marks with another half elsewhere (bookmarks, comment ranges, field characters) are never dropped. Comments go into `word/comments.xml` (made with its relationship and content type when the file has none) and their ranges cut the runs they start and end in, but never a revision: a range that starts or ends inside a `w:ins` (another's, or one just written) stands before or after all of it (`place`). A range mark inside `w:ins` is itself read as inserted, and LibreOffice then takes the unchanged words the range covers as inserted too, so rejecting the change would delete them. A table the manuscript has and the file has not is a `Wanted` of its own (`Wanted::table`, a `Table`: how each column is set and rows of cells, a cell its paragraphs, each a `Wanted` with looks, links and comments). It is matched with nothing: `rewrite` aligns the paragraphs only and writes each table after the paragraph before it (the ones before every paragraph before the file's first), every time anew, since a file is always written from the copy that was taken in. `Table::xml` is a `w:tbl` as wide as the text of the document's last section (`text_width`, the page without its margins; A4 with inch margins when the file does not say), with a grid of thin lines written into the table itself, so no style of the file is needed, the columns sharing the width as the window's preview shares it (`markdown::column_shares`), the first row in bold and marked `w:tblHeader`. A cell's paragraph has no style: its text is set like the nearest body paragraph's (`template`), with the first-line indent and the line spacing of running text taken off and `w:jc` from the column. It goes through `noted` and `dressed` as any paragraph, so a citation in a cell is a field and a comment has its range there. With `Options::track` every row carries `w:ins` and the cells' paragraphs are insertions. Two tables that touch are one table to Word and a body does not end in a table, so where a table made here would touch another one, or the last `w:sectPr`, an empty paragraph is written between (never between two tables of the file's own). `Rewritten::tables` counts them. `Look` has `strike` and `mono` for what a cell's Markdown sets so. The tests build small files; real ones are tried with the `docx` example and LibreOffice.

## 批注 and manuscripts from files (`comment.rs`, `manuscript.rs`)

A paragraph to be written can also carry what a reader of the file needs of a citation (`Wanted::anchor`, `links`, `looks`), put on after the text is settled (`dressed`): a look cuts the runs it starts and ends in and sets `w:i`, `w:b`, `w:vertAlign`… in the order the format wants them (`with_look`); a link is a complex field, `HYPERLINK \\l "<bookmark>"`, whose marks stand around the paragraph's own runs (inside an insertion when its words are one: `place` with `through`) and so are a 域 a click follows; the paragraph a link leads to is bookmarked under a hidden name (`_WPREF_n`, numbered after any the file has; the bookmarks take the `w:id`s before the revisions). A link whose anchor no paragraph has is left out. For a file cited anew (`restyle.rs`): `marks` gives the body's fields (code, and where the words they show begin and end; one inside another after it) and the raised words of each paragraph (`w:vertAlign`, or lifted by `w:position` as LibreOffice writes it); `unfielded` takes fields out whole, marks, codes and the fields inside them, leaving their words; `Wanted::edits` are a paragraph's changes as the caller knows them, made instead of the word diff when they do give the new text (the diff takes `grow1.` for one word); `Wanted::fresh` is a paragraph never taken for one of the file's changed, so a new reference entry keeps none of the old one's italics; `Wanted::level` takes what raised some words off them.

## Citation styles (`csl.rs`, `cite::Formatter`)

`cite::Style` is how a manuscript exported to Word cites: the two simple forms made here (`AuthorYear`, `Numeric`) or a CSL style (`Csl`), the definition files Zotero uses, processed by `hayagriva` (its `archive` feature carries some eighty styles and every locale; Science, PNAS and NEJM, which it lacks, are files in `crates/core/styles/` compiled in, `csl::SHIPPED`, and built in like the rest: `Builtin` is either kind). A style's key is what `Manuscript::cite_style` keeps for a manuscript that chose one (`Store::set_manuscript_cite_style`; a column added by `store::add_columns`, empty for a manuscript that follows the settings) and `Settings::cite_style` for those that chose none: `author-year`, `numeric`, `csl:<name>` (built in), `file:<file>` (added to `styles/` in the data root, `csl::add` / `save`; a file replaced is kept in `styles/removed/`), `zotero:<file>` (in `~/Zotero/styles`, read where it is; listed only when neither built in nor added, by the style's `<id>`). `csl::style` reads the key; a dependent style is its parent when that is built in or beside it, a style that cites in footnotes is refused (the built-in ones are known by name, `csl::in_notes`, so a list leaves them out without reading every style; a test keeps the names true). Every style cited with, built in or a file, is `mended` as it is read, in the two places `hayagriva` 0.10.1 reads a style wrong. A `<names>` with child elements and no `<name>` among them (`<names variable="author"><label/><substitute>…`, which CSL allows: the names are written with the options inherited from `<style>`) is taken for one that writes nothing (`Names::will_have_info`), so the built-in Vancouver (NLM) listed no authors, and where such names were written all the same the label stood before them (`, editorJones M`): it gets a default `<name/>` in front; one with no child elements at all is left alone, since in a `<substitute>` that is the short form that takes the `<name>` of the element it stands in for. And a date's `delimiter` is written before a part the date turns out not to have (`2024 ;10(3)` for a year alone in a form of year, month and day): `spaced` says it as affixes of the parts, on the side of each that faces the coarsest one, which is there whenever any is; the date forms of the locales get the same (`locales`). A test tries every built-in style on `cite::sample` and finds the first work's first author in its list; `alphanumeric` (Typst's own, which only makes labels) has no `<bibliography>` and so no list. The styles offered first are two lists by how they cite, `NUMBERED` and `BY_AUTHOR` (`common_numbered`, `common_by_author`; a test reads each style's own `citation-format`, `Loaded::numbered`, which is how Cell was found to number its references now and Frontiers not to), and `SHORT` is the name a built-in style is listed by where its title is long or says little (`short_name`: three titles begin 「China National Standard GB/T 7714-2015」), in Chinese, translated where shown. `csl::remove` moves a file of the person's to `styles/removed/` and gives back what it said, which `save` puts back. `cite::sample` is a style tried on three works of its own (seven authors; two, the first with two given names; a Chinese one of three: what tells styles apart in when they write "et al." and in what follows an initial), a sentence and the list: what 设置 › 写作 shows of a style; `Rich::raised_as_characters` writes what a style raises as `¹²³` for a place that draws nothing raised, and leaves a raised stretch with brackets on the line. `csl::render` gives every citation group and the list as `cite::Rich`: the text, its looks, and which words cite which paper (the processor marks each item of a citation, `ElemMeta::Entry`), with the locale of the manuscript's language. A paper is an article in its journal with authors, year, DOI and PMID (`csl::entry`); volume and issue go on the journal (the parent `Periodical`), the page range on the article, each as a number or range where it reads as one (`MaybeTyped`) so a style can shorten a range or give it an en dash, else as written (`S1`, `e1234`). `Formatter::rich` writes a text's groups (`apply` is its words alone) and `references` is the list with each entry's paper, so `manuscript::wanted` (given `Cites`) makes every citation a link to the entry's anchor; only groups whose every key names a paper count for numbers and entries. A CSL group cited again reads as it did the first time. Works that are no papers are cited from CSL-JSON (`csl::Record`, hayagriva's `csl-json` feature; `record_of` makes one of a paper): `render_records` takes groups of `Cite` (record id, a page, `narrative` for authors the sentence already names, written from the year on in a style whose citation says the year and whole in a numbered one) and the works to list uncited; a field of a record the processor cannot read is left out, not the record. The tools `list_cite_styles`, `read_cite_style` (a built-in one written out as XML, with the CSL namespace on its `<style>`, which `hayagriva`'s archive leaves out and Zotero asks for: `adjust::in_namespace`), `try_cite_style` (a style or a CSL text tried on the library's papers, kept nowhere) and `save_cite_style` (in `WRITING`, not asked about: it adds a file the person then chooses in the export menu) are how the assistant makes a style to the person's wishes.

## A style's details changed (`adjust.rs`)

`adjust::Knobs` is the few details of a CSL style most often asked to be otherwise (WispStudy issue 314): a numbered style's `brackets` (`Square`, `Round`, `Bare`) and whether its number is `raised`; for a style that cites by author and year, when a citation says "et al." (`cited`, a `Cut`: with `min` authors or more the first `first`; `min` 0 is never); when an entry of the list does (`listed`); and what stands after an initial (`initials`: `. `, `.`, a space, nothing). `read` finds them in the style's XML where the common styles say them. The number is the `<text variable="citation-number">` that the citation's own layout holds, with the groups around it up to the layout (IEEE's brackets are on a group around each number, GB/T's number is raised and in brackets at once); "et al." is on `<citation>` or `<bibliography>`, else on a `<name>` that is not the short form (IEEE), else on `<style>`; `initialize-with` is on the names, the list or the style. `write` puts the details of a wanted `Knobs` that differ from the style's into the XML attribute by attribute (`tags`, `attributes`, `with`: the tags as written, found with `docx::node`) and leaves the rest of the file as it was written, comments and quotes included: brackets go to the layout, around the whole citation; a name that said for itself when it is cut follows the list from then on; `et-al-subsequent-*` go, so a later citation is cut as the first is; `first` is brought under `min`. Nothing asked gives the text back unchanged. citationberg's own types are not what is changed: its `Name` keeps its options private, and a file written by hand should keep what it says.

`knobs` is `read` without what does not show: each detail found is changed once and the style's `cite::sample` compared, so a detail said in a place not known here, or of no effect, is not offered (what follows an initial in Chicago, which writes given names in full). A test holds every style offered first to it: each offers its number or its "et al.", and what is offered is read back as written, leaves the other details alone and changes the sample.

`keep` saves a changed style. A file of the person's own (`file:…`) is written over through `csl::save`, what it said kept in `styles/removed/`. Any other stays as it is and becomes a new file `<name>-adjusted.csl` (`-2`, … while taken) made by `copied`: the CSL namespace on `<style>`, an `<id>` of its own (`urn:wisp-study:style:<file>`), the title given, the link that called it itself turned into `rel="template"`, and at its head the comment `<!-- Wisp Study: adjusted from <key> -->`. `base_of` reads that comment, so a copy changed again is named after its base anew; `kept` finds the copy of a base that already reads as wanted, so the same change is not kept twice. The title is composed in the window (`cite_styles::adjusted_title`), where the words are translated.

## A Word file cited anew (`restyle.rs`)

`restyle.rs` restyles the citations of a Word file that was written elsewhere and is no manuscript of the app. `inspect` reads what it cites, in this order of trust. Fields of Zotero's (`ADDIN ZOTERO_ITEM CSL_CITATION {…}`, Mendeley's `ADDIN CSL_CITATION` too) carry every work as CSL-JSON (`itemData`), so nothing is guessed; a field with a prefix or suffix, one edited by hand in Zotero (`dontUpdate`), an author-only one or one with a locator that is no page is left whole and said (`Found::problem`). Without such fields the file is read as text (EndNote's `ADDIN EN.CITE` and Word's own `CITATION` are recognised and said to be what they are; their data is not read): the list is the paragraphs of a list field (`EN.REFLIST`, `BIBLIOGRAPHY`) or those after the last heading `headings::opens_references` knows, up to the next heading; each paragraph is an entry, numbered by its label (`label`: `[3]`, `3.`, `（3）`) or its place. The body's citations are found by number (`numbered`: square brackets, and raised numbers, which are not a unit's power) and by author and year (`author_year`: `(Zhang et al., 2024a; Li & Wang, 2019, p. 5)`, `Zhang et al. (2024)`, `（张三等，2020）`, matched to the entry of that year whose first author is so named, the letter and the second author telling two apart); the file cites the way more of them are found. An entry becomes a record (`resolve`): the library's paper (DOI, PMID, or its title standing in the entry's text; the entry's own volume, issue and pages where the record has none), a Crossref lookup of its DOI, its own text read by rule (`parse_entry`: GB/T 7714 with its `[J]`, author-date, and year-last forms; a guess, said so), a Crossref search by its words (kept only when the record's title stands in the entry), or one the caller gives (`given`: the assistant reads a reference better than rules do). The network is a `sources::Fetch`, asked only when given. An entry that could not be read (`UNRESOLVED`) stays as written at the list's end, and so do the citations that name it; nothing is dropped or made up. `Inspected::report` is what the tools hand back. `restyle` renders with `csl::render_records` (entries nothing cites are kept in the list, after the others) and writes with `docx::rewrite`: each citation an exact edit of its paragraph (`Wanted::edits`) with links to the entries' anchors, the old list's paragraphs replaced by new ones written afresh (`Wanted::fresh`), the fields of rewritten citations and of the list first made plain text (`docx::unfielded`), so no field of Zotero's is left half rewritten. A raised number that becomes words is set on the line with a space before it (`Wanted::level`), words that become a raised number lose the space. A style that writes no list leaves the old one. Tools: `read_docx_citations` (read-only) and `restyle_docx` (in `WRITING` and `CONFIRMING`; `output` never an existing file, by default beside the source as `-restyled`), both with `lookup` and `entries`.

The same reading makes a library of what a file cites: `works` gives each entry of the list as a paper (`csl::paper_of`, the other way from `record_of`: `Family, Given`, a Chinese name written together, a DOI, PMID or year a paper may not hold left out) with how it was read and how often it is cited; with `fetch`, an entry read from its own text that names no DOI is searched on Crossref by its words (`searched`, the same search `resolve` makes for an entry it cannot read) and a record whose title the entry says, of its year, gives it the DOI and what else the text left out. The tool is `import_docx_references` (in `WRITING` and `CONFIRMING`; `lookup` on unless turned off): the papers come in through `Store::import_papers` with `source` 「导入 · <file>」, deduplicated as any import, no import batch; an entry that could not be read is not made up but returned in `unresolved` with its words, for the caller to read and give back as `entries` (then only those are taken, without the network); `checkAgainst` are the ones read by rule alone. `restyle::note` and `ai::manuscript_review_note` tell the assistant the tool is there.

`comment.rs` is 批注: `manuscript_comments` (made beside the library's tables, no version bump), each about a quotation of its section and found again by what it says (`locate`: as written, else by its characters without spaces and quote styles), from a Word file (`FILE`: never removed, only marked `DONE`), the person, or the assistant. `review_prompt` / `parse_review` are the assistant's review of a section: a JSON list of `{quote, comment, replacement}`, each quotation checked against the text (kept only when found within one paragraph and not overlapping an earlier one). A proposal is taken only by the person (`Comment::taken`: the comment moves to the new words and keeps the old; `taken_back`). `manuscript.rs` has the rest: `from_word` / `from_markdown` make a `Draft` (sections at the highest heading level; a Word file without heading styles has its headings guessed by `headings::guess` (a name every paper has, numbering `一、` / `（一）` / `1.1`, a figure at the end `（图1）`, bold, a short line between running text; numbered items next to each other are a list, nothing after 参考文献), listed in `Draft::headings`, and is cut only at those the person ticks in `Modal::Headings` (`from_word_with`); a Markdown file without headings at `structure::canonical` names; a title; `bare` for text under no heading), `Store::split_section` / `merge_section` are 设为标题 / 从这里拆成新节 under the editor and 并入上一节 in a section's menu: a heading made of a paragraph is written back as that paragraph, a section cut off without one is `bare` and its name goes into no file. `Store::manuscript_blank` says whether a manuscript is still the empty one 写作 opens a library with (no title, the IMRaD sections without a word, no snapshot, comment, conversation or source file), and `Store::retire_blank_manuscripts` puts such ones away when a real one is made or taken in, so no stray 未命名稿件 stays beside it. `Store::import_manuscript` keeps it with the Word file itself under `manuscripts/` and a `manuscript_sources` row, `wanted` lays the manuscript out as the file's paragraphs with the comments on them, and `Store::manuscript_word` is the export (the source file written again, or `docx()` with comments for a manuscript that has none). A pipe table written in a section (`table_rows`: `markdown::table_lines` at a line that is no code, list item, heading or quotation, the same test `section_markdown` keeps its rows together by) is a real table in the Word file. `word_table` reads its lines (`markdown::pipe_table`) into a `docx::Table`: a cell's Markdown marks become looks, `<br>` a new paragraph, and each stretch of a cell goes through `cite::Formatter::rich`, so its citations read and link as a paragraph's do (the formatter is made from the sections' whole text, a table's lines included, so a paper cited only in a cell is numbered and listed). `wanted` pushes the table as one `Wanted` in the lines' place; a comment whose words a cell says is put on that cell (`saying`). For the document made here, `document(manuscript, false)` leaves the tables out and `docx::rewrite` puts them in with their fields and comments; `docx()` alone (`document(…, true)`) writes them plain (`Table::plain`). Nothing reads a Word file's tables into a manuscript: one exported and taken in again has the table in its file and not in its text. `read_manuscript` lists a section's open comments.

## 配引用 (`citefind.rs`)

`citefind.rs` is 配引用: the papers of the library a text can cite, sentence by sentence, and nothing that writes a word of the manuscript's. `sentences` cuts a text and keeps where each sentence stands (full stops of either script, semicolons, line breaks; not after an abbreviation, inside a number or inside brackets); `plan_prompt` / `parse_plan` are what a model says of each sentence before the search: what it does (`INTENTS`: background, a finding of someone else's, a method, an open question, a comparison, the authors' own words) and the search words for it in the library's language (`library_language`; `words_prompt` / `parse_words` are the words alone, which 出处 uses); `search` ranks the papers for every sentence, each query twice (by the record, and by the paper's best sentence among the abstract's and the stored full text's, over `retrieval::index_for`), merges the rankings and names the sentence that matches best, keeping a paper only when record and sentence hold a fair share of a query's words. What a sentence can cite goes by what it does: for a finding, a comparison or a method a sentence outside the paper's introduction is named when one fits, background puts the reviews first (`reviews`: a full text without methods or results, or a record that says so), the authors' own words are not searched for. `named` reads the works a paper's sentence names by author and year (`(Tang et al., 2009)`; numbered citations name nothing, the reader leaves raised numbers out) and `holds` finds the library's paper for one. `judge_prompt` / `parse_judgement` are a model's choice among the papers found, by a standard per intent (a JSON list of sentence, `cite` with key, role `SOURCE` or `REVIEW` and why, and `restates`: papers that only tell what others found, which are no citation but a lead to the works they name; it chooses, it never names a paper of its own); `place` / `placed` write `[@A; @B]` before the mark a sentence ends with, into a citation already there, never a key twice. The tool `find_citations` (text, optional `queries` and `intents` per sentence, `perSentence`) is `sentences` plus `search`, each candidate with `review` and the `names` of its sentence.

## 出处 (`passage.rs`)

`passage.rs` is 出处: the sentence of a paper that a citation of the manuscript rests on, so a reference leads to where it is from and not only to the paper. `cite_passages` (made beside the library's tables, no version bump) keeps one per manuscript, paper and citing sentence (`claim`: the sentence without its citations, `passage::claim`), with the paper's sentence, its part and page, why, and where it is from (`CITED`: the person cited from that sentence; `MODEL`: looked for afterwards and chosen by a model; `WORDS`: found by words alone, unchecked). Nothing is written into the manuscript, whose text stays `[@Key]`: `citations` gives every citation its sentence and `assign` finds its passage again by how alike the claims are (`docx::likeness`), so it stays with the sentence while the text is written on; a sentence written anew or translated takes the paper's unclaimed passage of that section, said to be `loose`. Looking afterwards: `sentences_of` is what a paper says of its own (the abstract's sentences, then the stored full text's), `nearest` ranks them against the sentence and any search words (BM25, merged; `fair` when one holds a fair share of the words), `choose_prompt` / `parse_choice` are a model's choice among them, which may be none: then a row without a passage is kept (`Passage::found`), said under the reference as a citation its paper does not bear out, and not asked again. The tool `find_passages` (paperId, `texts`, optional `queries`) is `sentences_of` plus `nearest`; `read_manuscript` lists each section's passages. `Store::merge_section` / `split_section` take the passages along, and `cite::convert_ai_citations` hands back the sentences an answer quoted (`Quoted`) for `passage::quoted`.

## An assistant's changes to a section (`revise.rs`)

`revise.rs` is a change to a section of a manuscript as the words to find and the words to put there (`Edit`; no words to find is the end of the section, no new words a deletion): what `edit_section` takes through `compose` (`write_section` takes a section's whole text), and what the window lists of 助手写's changes. `find` / `place` say where a change goes in the text as it now stands (as written, nearest to the last change, else by `comment::locate`; a paragraph taken out takes its empty line along), `follow` keeps a place while one stretch of the text changes around it, `added` is the new words to light up (`ai::word_diff`). No store, no tool, and no prompt: the reply format and the prompt of 改稿 (SEARCH/REPLACE blocks read as they streamed) went with its box under the manuscript.

## 助手写 (`compose.rs`)

`compose.rs` is 助手写, the writing page's other mode, in which the assistant leads: the person talks with it and it writes the manuscript with three tools of its own. `edit` is the tool `edit_section`: changes to one section, each made where its words stand (`revise::place`; no words to find is the section's end), and what no change names stays as it is. `write` is the tool `write_section`: a section's whole new text, for a section with nothing in it or one the person wants written anew. The two were one tool that took `edits` or `text`, and which it did was left to how a model filled the call in: one model (Kimi K3), meaning a change, began `text` instead in half of its calls, and sent it empty (refused), or a note to itself (kept as the section: 15 characters where 7,400 stood), or one paragraph of a section of 8,000. What a call does is now its name; asked the same things through `model_probe` (debugging.md), the same model made 19 of 36 writing calls with `text` before and none of 25 after, with fewer steps. ## 图片库 (`figure.rs`)

`annotation.rs` is the marks on a PDF, kept apart from the file in `pdf_annotations`: an underline or a highlight of one page, the text it covers, a box per line in the page's points, a note, and for a highlight its colour (a key of `COLORS`, the `color` column added by `add_columns`; empty for an underline, and a highlight from before colours reads as the first). The range of a mark never changes; its note (`update_pdf_annotation_note`) and a highlight's colour (`recolor_pdf_annotation`) do. Tool: `list_pdf_annotations` (read-only). A piece of a page marked to be cut out later (`Kind::Cut`, 截图标记) is a row of `pdf_cuts`, a table of its own because the CHECK of `pdf_shapes` in libraries already made allows two kinds: its rectangle and a note, no picture. It goes through the shapes' functions (`add_pdf_shape`, which keeps the same place once, `move_pdf_shape`, the note, the removal) and is read back by `pdf_annotations` with the rest. A text box written on a page (`Kind::Text`, #227) is a row of `pdf_texts`, a table of its own for the same reason (a build from before it does not know the table and leaves it be, so `SCHEMA_VERSION` stays): its edges, its words in `note`, and the keys of its fill, border and ink (`TEXT_FILLS`, `TEXT_BORDERS`, `TEXT_INKS`, read back as `Annotation::style`, a `TextStyle`; a key this build does not know reads as the default's, a pale yellow card with black words). `add_pdf_text` keeps none with nothing written, `restyle_pdf_text` changes the colours, `move_pdf_shape` and `remove_pdf_annotation` take it as the other shapes, and `update_pdf_annotation_note` with nothing left in it removes it. It moves with its paper (`take_paper`) and `list_pdf_annotations` lists it as `text`. Undo (#273): `Change::between` is what a write did to a file's marks, from `pdf_annotations` read before and after it (each mark touched as it was and as it is, `None` where it is not; only `updated_at` changed is no change), and `History` keeps a file's changes to take back and to do again (at most 100, a new one clears the redo side). `Store::step_pdf_marks` takes one back or does it again in a savepoint, all of it or none; it writes with `restore_pdf_annotation`, which puts a row back in its own table exactly as the `Annotation` has it (`INSERT OR REPLACE`: the same id, both times, place, words and colours), so a mark removed comes back as the same mark, and a mark made by the change is removed. A mark of a file removed since cannot come back: the step fails and is dropped.

`handles.rs` is the geometry of a rectangle chosen on a page (a box, a marked piece, the figure dialog's frame, a text box), in the page's points, with the reaches handed in as points (screen pixels over the page's scale): `HANDLES` (the eight, as the edges each moves), `handles` (the middle of a side only where the side is longer than four reaches), `grab_at` (a handle, the nearest, else the edge as `Grab::Body`; nothing inside), `on_edge`, and `drag`, which moves a rectangle on its page or sizes it by a handle, each moved edge stopping at the page's border and `MIN_SIDE` short of the edge across from it. The window's side is in `docs/dev/app.md` (Boxes and sticky notes).

`figure.rs` is 图片库: pieces cut out of PDF pages and kept as pictures under `figures/` in the library folder, one `figures` row each (number, legend, notes, tags of their own, and the paper, file, page and box they came from). The table is made beside the library's own like the manuscripts'; no version bump. `caption` finds the caption a piece belongs to among the page's lines (`pdftext::lines`): a line that `opening` takes for a caption's start (`Fig. 2 |`, `Figure 3.`, `Table S1`, `Extended Data Fig. 4`, `图 3`; not running text that begins `Figure 2 shows` or `Fig. 2a). These`), the nearest within `REACH` that shares the piece's columns (a figure's under it, a table's over it), read on through the lines set alike under it. `Ask`, `ask_prompt` and `read_legend` / `read_tags` / `read_notes` are what a model that sees the picture is asked and how its answer is read. A figure is listed while its paper is outside the trash; `delete_paper` and `remove_figure` set the picture aside in `removed/`. A picture a model drew is a figure without a paper (`paper_id` empty, `Figure::drawn`): so `paper_id` is no reference to `papers`, a trigger takes a deleted paper's figures along instead, and `figure::migrate` makes over the table of a library from before (same columns, so an older build reads it as before). A picture the person brought in from a file of their own is a figure without a paper too, told from a model's by `origin` (`UPLOADED`; `Figure::uploaded`, and `drawn` is false for it) and keeping the name of the file it was (`file_name`, which `matches` looks through); both columns are added by `store::add_columns`. `picture_size` reads the size a PNG or a JPEG says it has. Tool: `list_figures` (read-only; it gives each figure's `address`, and its description tells a model how a manuscript shows one).

A manuscript shows a picture on a line of its own, `![caption](figures/G….png)`: the address is the figure's place in the library folder, so the Markdown is Pandoc's as it stands. `markdown::picture_line` reads such a line (the caption may hold brackets, a citation; the address none), `markdown::lines` gives it `Line::picture` and the caption's pieces between two pieces of syntax, and `plain` says the caption. In `manuscript.rs`, `picture_lines` lists a text's pictures (fenced code is not looked into), `library_picture` says whether an address is a file right under `figures/` (nothing else is ever read), `pictures_used` the ones a manuscript has, `picture_markdown` writes the line and `place_picture` says where it goes into a text being written. A picture without a caption says nothing in `plain_text` and in a Word file. In a Word file (`Store::manuscript_word`) a picture's line is its caption, cited like any paragraph, with the picture over it; one without a caption stands under the paragraph before it. `manuscript::wanted` hangs them on the paragraphs (`docx::Wanted::above` / `below`), and `docx::rewrite` writes each as a paragraph of its own holding a drawing (`Media`: the parts under `media/`, the relationships, the content types; the names said on the elements, so the file's root need not have them; `picture_extent` keeps one within a page). It is the same for the file made here and for the file a manuscript came from, which gets them put in beside the paragraphs it had. A picture whose file is gone, or a WebP, which Word does not read, is named in `Rewritten::left_out` and leaves its caption alone.

A Markdown file taken in as a manuscript brings the pictures it shows from files of its own, so a draft written and laid out elsewhere arrives whole. `from_markdown` keeps a picture's line a paragraph of its own whatever stands right over and under it, without Pandoc's attributes (`{width=80%}`). `pictures_beside` lists the addresses with the files they name, read from the folder the file is in (`file_beside`: relative, percent-decoded, or a full path; a link is `Left::Link`, nothing is fetched); `read_pictures` reads them, a PNG or a JPEG as it is, any other kind through the caller's `anew` (the window writes a PNG as 资料库 does for an upload, `write_figures::as_kept`; a tool passes none, and a WebP is then kept as it is); `Store::bring_pictures` keeps each as a figure of the person's own (`UPLOADED`, the file's name, the caption as the legend), one the library already holds to the byte not twice (`Store::figure_holding`), and writes the draft's lines with the addresses in `figures/`. It runs before `Store::import_manuscript`; what did not come keeps its line and is told with its reason (`Brought::left`, a `Left`, whose `said` is in `locales/en.json`). A line the library's own export wrote, read where its picture is not beside the file, is left alone when the figure is here.

## 方法库 and 导言库 (`excerpt.rs`)

`excerpt.rs` is 方法库 and 导言库: passages kept from a library's papers in their own words, one `excerpts` row each, of two kinds told apart by `kind` (stored English keys `METHOD` = `method`, `INTRO` = `intro`; `KINDS` is the label table, translated where it is shown): an experimental method, or how a paper's introduction leads into its question. Each has a name (for a method what it is, for an introduction how it leads in), the paper's words as they were selected in the PDF (`text`), the person's notes, tags, and the paper, file and 1-based page the words stand on; one the person wrote down themselves has no paper (`paper_id` empty). The table and its link table `excerpt_figures(excerpt_id, figure_id, position)` are made beside the library's own after the figures' (`store::SCHEMA` runs `excerpt::SCHEMA` last); no version bump. `paper_id` is no reference, as with figures: triggers take a deleted paper's excerpts along, and a deleted excerpt's or figure's links. An excerpt has no file, so `remove_excerpt` is a plain row deleted. `list_excerpts(kind)` gives those of a kind (`None`: both) whose paper is outside the trash and those without one, the newest first; `save_excerpt` changes the words, never the kind or the source. The links are the person's and kept for any kind, though the window sets them for methods only: `set_excerpt_figures` replaces an excerpt's set in the order given, passing over an id that is no figure; `excerpt_figures` / `figure_excerpts` read one side, `excerpt_links` all of them for the window's cache. `Excerpt::matches` looks through the name, words, notes, tags and the paper's title, authors, journal and year (with `figure::search_words`), `tag_counts(excerpts, kind)` counts the tags of one kind. `hand_file` hands a file's excerpts over with its marks and figures, and `take_paper` brings a paper's excerpts along with their links to the figures that came with it. Tools: `list_methods` and `list_introductions`, one implementation (`tools::list_excerpts`) with the kind; read-only and in `ACROSS`. `id` finds one (a passage named with `@` whose words the note gave only in part). Each passage comes with its paper and page, a method also with the number and legend of its linked figures. Their descriptions tell a model when to read them (summarising, comparing or choosing methods, a parameter's evidence; how others open and lead in) and not to take the notes for the paper's words. No tool writes one: keeping a passage is the person's action in the window.

## 收藏 across libraries (`collected.rs`)

`collected.rs` reads what every library holds under 收藏 for the home page's star (`src/collected.rs`): `read(info)` opens a library's store and makes a `Held` of it (the starred papers, `list_figures`, `list_excerpts(None)`, `excerpt_links`, and as `sources` the unstarred papers a figure or a passage is from, so each can say where it is from; the other papers are dropped), `merged(held, kind)` is everything of a `Kind` across the libraries as (library, place), the newest first by `added_at` with the shelf's order between equals, and `shown` narrows that to one library and to the words of a search (`paper_matches`, `Figure::matches`, `Excerpt::matches`). A passage's place is in `Held::excerpts`, which holds both kinds. `star(dir, paper, starred)` is the one write. It is not a tool: an assistant reads across libraries through `tools::ACROSS`.

## Figures a text points at (`figref.rs`)

`figref` is what the reader needs to show a figure from its number in the text (#229). `mentions(marks)` reads a page's glyphs as one text (a space where a line ends) and finds every "Fig. 3B", "Figs. 2 and 4a–c", "Supplementary Table S1", "Extended Data Fig. 4", "图 3", "附表 2": each a `Mention` (the first and last glyph, and a `Key`: `Kind` figure / table / scheme, `Series` main / supplementary / extended, the number). An S before the number puts it in the supplement's run whatever word comes before; a list gives one mention a number ("Figs. 2", then "3"), and a comma lists only after a plural, so "in Fig. 2, 30 cells" is one figure; "Figure 3.5" (a book's numbering by chapter), "config. 3" and "Tablet 2" name none. Panel letters are part of the mention's words and of nothing else: where a panel stands in its figure is not known. At the end of a run ("Figs. 2–5", "2 to 5": `listed` says "through") the last number stands for the figures between as well, since they are written nowhere else: `Mention::since` is the first of them and `keys()` all (`RUN` at most), so a click on the `5` offers 3, 4 and 5. `key_of` reads a caption's label the same way.

Where a figure is: `shown(marks, shapes, page)` takes the page's captions from `figure::caption_spans` (the reader of 图片库, now also saying which lines a caption takes) and, for each, the piece of the page its figure takes (`region`). A PDF does not say what a figure is, so it is what the page draws by the caption: `pdftext::page_drawn` gives, beside the glyphs, the box of every picture and path as far as its clip lets it show (`Marks::shapes`, read only when asked for). `gathered` takes the shapes abreast of the caption and within `FROM_CAPTION` over it, then those within `BETWEEN_PARTS` of what it has (or beside it by less than a column's gap, `BESIDE`, unless they stand over another caption), never past the caption of the figure above; under the caption when nothing is over it. A shape that fills the page is its ground; one thinner than `RULE` starts no figure but joins one it touches, as do short lines of text by it (an axis's numbers, a panel's letter). A table is what stands between the rules under its caption (`TABLE_TOP`, `TABLE_ROWS`). `Shown::weight` tells a caption from running text that begins a line with "Fig. 3. The…": set apart from the line before, a bold opening, a legend, a figure found.

`Index` holds every page's `shown` and what the page draws that none of its captions claims (`unclaimed`, at least `ALONE` large). `settle`, once all pages are in, gives captions without a figure the figures without a caption: a legend that opens its page (`CARRIED`) takes what the page before draws, and legends still alone are a list of them whose figures follow on pages of their own, matched in order only when there are as many of the one as of the other (a preprint's manuscript). `find(key)` is the surest caption of that number, the first of equals; a `Place` is its page and, when the figure is on another, that page and piece (`apart`), and `pieces` is what to look at in reading order. `own` says a mention stands within the figure it would lead to. Among a paper's files, `places(key, files, here)` is where a number written in one of them may lead: this file's figure first, then the others'; the supplement's and Extended Data's numbers are looked for in every file, a plain number only in this file and, written in an attachment, in the main text (the main text never means an attachment's Figure 3 by "Fig. 3"); and when no file has the supplement's figure by that name, an attachment that numbers its figures plainly is what "Supplementary Fig. 2" means. More than one place is a choice for the reader. The other way, from a figure to the text: `spoken(page, marks, section)` gives each mention of a page with the paragraph it stands in (`pdftext::page_paragraphs`, the nearest when it stands in none): one box per line of its words, the paragraph's box, and its text as it is shown (`snippet`: whole when short, else from the start of the sentence that names the figure, `SNIPPET` characters; the stop of "Fig." ends no sentence), and the part of the paper, carried from page to page and changed by a one-line paragraph that `structure::canonical` knows as a part's heading (the back matter is no part). `speaking(place, there, files, spoken)` is every such mention in a paper's files that may lead to one figure (`places`, so the same rules hold both ways), the main text's first, a paragraph that names it several times once, and never a caption's own number, in whichever file. `opens` says a mention is the number a figure's caption opens with. `file_index` reads a whole file page by page (`pdftext::pages_drawn`, which keeps one page at a time) into a `Read`: the index, what is spoken, the pages' sizes. Nothing here is stored: it is read from the file each time it is opened. Left out: figures with no caption on any page, the place of a panel, and a caption that manuscripts set double-spaced is read to the end of its first line only (`figure::read_caption`'s leading). The example `structure -- a.pdf figures` prints what each page draws, every place found and what every mention leads to.

## Slides (`pptx.rs`)

`pptx.rs` writes a PowerPoint file by hand, as `manuscript::docx` writes a Word file: a zip of XML parts, stored (`manuscript::stored_zip`), no dependency. A `Deck` is a title, a subtitle and `Slide`s; a slide is a title, `Point`s of two levels (`Point::read` drops a list marker and takes two spaces or a tab in front for a point under the one before; `**bold**` and `*italic*` are looks, read by `markdown::inline`), a `Picture` (PNG or JPEG, its size read off its header: `figure::png_size`, `jpeg_size`; WebP is refused, PowerPoint before 2021 does not read it), a caption, a source for the foot and notes for the speaker. Whoever makes a deck says what is on a slide, never where: `lay` gives every slide of the file its `Page` of frames in points (a slide is 960 by 540), and `write` turns pages into parts. The first slide is the deck's title; a slide with a title alone opens a part of the talk; a picture stands under the points when it is wide (twice as wide as high, and the points leave it most of the slide), beside them otherwise (a tall one in a narrower column), or alone.

A text box of a .pptx does not shrink its words, so the fitting is done here. `line_count` estimates the lines of a text at a size in a width from the widths letters usually have (`advance`: Arial's by kind, rounded up; a Chinese letter is as wide as it is high and a line may break after it), since no font is at hand. The points get the largest of `SIZES` at which they fit (`fitted`); points that fit at none are counted out at `SPLIT` (`taken`: never none, and never a point without the one it stands under) and go on to a slide of the same title with 「（续）」 / ` (cont.)`, without the picture and the notes. A heading is on one line at the largest size it can be, else on two. A caption longer than `CAPTION_LINES` is cut with an ellipsis and then stands whole in the notes. `Written` says which of the deck's slides went on and which captions were cut, for the tool to tell.

The parts: one master, one layout (title and content) and one theme; the title and the points of a slide are placeholders of that layout (so PowerPoint's outline shows them and a theme chosen later reaches them), everything else a text box, and every size, colour and place is written on the slide itself, so the three programs draw it alike. The number at the foot is a field (it follows a slide that is moved). Notes need a notes master with a theme of its own; both are written only when a slide has notes. A picture shown on several slides is in the file once. The theme names no East Asian font outright (`<a:ea typeface=""/>` with fonts by script, as Office's own themes): PowerPoint then takes the font of the text's script and every other program its own. When changing the parts, keep to the order of children the schema gives (`a:pPr`: spacing, then bullet colour, font, character; `a:rPr`: fill before fonts; `p:spPr`: place, shape, fill, line): PowerPoint refuses a file LibreOffice reads.

The tool is `make_slides` (`tools/local.rs`, in `WRITING` and `CONFIRMING`): `slides` of `title`, `bullets`, `figure` (an id of 图片库: its legend becomes the caption and its paper, number and page the source, unless given) or `image` (a PNG or JPEG of the machine), `caption`, `source`, `notes`; `paperId` gives the title, the subtitle and every slide's source when they are not said. A picture that cannot go on a slide is left out and said in `notes`, the slide is still made. `output` is never an existing file; without it the file goes to the person's documents under the deck's title. The slash command `/slides` (`ai::SLASH`) is the request that has the assistant read the paper, look up its figures and call the tool.

A reference (`slideref.rs`): a PowerPoint file of the person's (.pptx, .potx) that new slides are made after. `Reference::read` reads it once for two uses. For whoever writes the deck: each slide's title (its title placeholder), its other texts by level in the order they were drawn (a table a line a row; the number, the footer and the date left out), its notes and how many pictures it has, the layouts in use and the theme's fonts and colours (`Theme`; `Palette` looks a scheme colour up through the master's `p:clrMap`). For the writer: `Stage`, where a title and what is under it stand on three layouts (`Place`: the title page's, a part opening's, every other slide's), each a `Holder` with the `<p:ph …/>` a slide names it by, its frame (the layout's, else the master's placeholder of its kind, else the app's own places scaled to the slide) and the sizes its letters may have, from the size the layout or the master gives down (`title_sizes`, `text_sizes`). The layouts are chosen as the file uses them: the content's is the one most of its slides stand on among those with a place for text (`obj` before `tx` before others; vertical ones never), the title page's is the first slide's when it is a title layout, the part opening's the `secHead` of the same master. `Reference::drawn` says that most slides with words have no title in a placeholder (boxes drawn on blank layouts): the layouts are then chosen by kind, and the tools say that the new deck will not look like those slides.

`pptx::write_on(deck, &reference)` writes the deck on the reference: `lay` takes the `Stage` (`Rule` measures the points with the layout's sizes, the master's margins of its levels and the insets of its text; `held` sizes a title for a frame it cannot grow out of), and `slide_xml` fills the layout's placeholders saying frames and sizes only: colours, fonts, bullets and alignment are the layout's (a point is `<a:pPr lvl>` with its line and paragraph spacing, since the fit was measured with them). A picture and its caption have no placeholder and are laid out inside the text's frame as in the app's own design; the caption and a foot line without a place are drawn in `Place::soft` (the text's colour part of the way to a plain background; on the title page the title's colour). The line at the foot and the number go in the layout's `ftr` and `sldNum` placeholders where it has them; a layout without a place for the number shows none. The file is the reference's parts that a deck keeps (`Reference::kept`: everything the presentation leads to through `KEPT` kinds of relation and what that leads to, so a picture only its slides showed is gone, as are the views, the printer's settings and `docProps/app.xml`), its presentation with what it said of its slides taken out (`DROPPED`: the slide list, sections in `p:extLst`, custom shows) and the new list put in after the masters' lists, its relations renumbered after the largest id, and content types rebuilt for the parts that are there (a template's main part becomes a presentation's). Notes use the reference's notes master, or the app's own under names that are free. A new picture gets a name no kept part has.

The tools: `read_slides` (`path`, `from`, `count`; read-only) is the reading for a model, sublevels set in by two spaces as `make_slides` takes them, with `asReference` (the three layouts) and `caution` when `drawn`; `make_slides` takes `reference` (a path) and reports the layouts used. `slideref::note` is what a question that came with PowerPoint files tells the assistant.

Checking a file: `xmllint --noout` on every part of the unzipped file, then LibreOffice (`soffice --headless --convert-to pdf`). LibreOffice run from a shell on macOS sees only the fonts it brings along, so Chinese is drawn as boxes whatever the file says: start it with a profile of its own that has a Chinese font (`-env:UserInstallation=file://<folder>`, the font copied to `<folder>/user/fonts/`).

## Diagrams (`mermaid.rs`)

`mermaid::draw(source, &Palette)` turns Mermaid source into an SVG (`Drawing`: the SVG and the size it was laid out at). The reading, layout and drawing are the `merman` crate's (a port of Mermaid 12 without a browser; Zed embeds it the same way), built without its default features: those bring the ELK layout, which is EPL-2.0, so `layout` is set to `dagre` (dugong) and `layout-cytoscape` (manatee) serves mind maps and architecture diagrams. What this module adds:

- The look: Mermaid's `base` theme with every colour it derives others from set to one of the `Palette`'s (`config`), `pie1…` and `cScale…` to its `series`, the label's wrapping width raised from 120 to 220 pixels and the least node width lowered from 120 to 48 (names and paper titles are longer than the one and shorter than the other). `Palette::light()` is a white page; the window makes its own from the theme.
- An SVG a plain renderer draws as meant (`plain`, after merman's `SvgPipeline::resvg_safe()`, which already replaces `<foreignObject>` labels by `<text>`): the root gets the size of its `viewBox` in place of `width="100%"`; a label's box no longer clips (`overflow:visible`), since merman reckons a label's width from tables and the font actually found may set it a little wider; the ground under an edge's label is opaque.
- Bounds: `MAX_SOURCE` bytes, and a panic inside merman is caught and becomes an error, so whatever a model wrote costs one diagram and not the window.

An error is merman's own sentence (which token, where). `is_mermaid` says which fence languages are diagrams (`mermaid`, `mmd`). `cargo run -p wisp_core --example mermaid -- a.mmd [dark] > a.svg` writes the SVG or says why there is none. The rule in `ai::RULES` tells the assistant it may answer with a diagram to quote labels that hold brackets or punctuation (the most common reason a model's diagram does not parse), and to leave the colours alone: a `classDef` with a light fill and no text colour is unreadable in the dark theme.

## Mind maps (`mindmap.rs`)

A paper's mind map is a tree (`MindMap`: a root `Node` and the id the next node gets; ids are never used twice, so the node chosen in the window stays the one chosen through every change). A node is a few words, optionally an `Anchor` (a file of the paper, a 1-based page, the words there) and whether its children are folded away. Every change is a method that says what to choose next or whether anything changed (`add_child`, `add_after`, `remove`, `set_text`, `fold`, `indent`, `outdent`, `shift`, and `move_node`, which a drag in the window ends in: a node with what hangs on it to `Place::Under` another (its last child, unfolding it) or `Before` / `After` it; never into itself, never the root, nothing beside the root), and the arrow keys are `step` over the map as it is drawn (`shown`: what hangs on a folded node is not).

- As text it is an outline (`outline`, `from_outline`): the root as a heading, the rest a nested list, a node's passage after its words as `[p.5 "…"]`. `from_outline` reads what a model writes rather than only what `outline` writes: bullets and numbers, indentation of any width, further headings as levels, a code fence around it, emphasis round the words, `[P1 p.5 “…”]` and `[第5页 "…"]`; a line that is no item is not a node, and square brackets that name neither a page nor a quotation stay words (`[2012]`, `[Supp. 3]`).
- Passages follow the rule for quotations: `keep_found` keeps an anchor only where `locate` finds its words, and `read_reply` does that for a model's draft with `ai::locate_quote` on the pages of the file (the page named, when the words are there; else the first page that has them; a quotation of fewer than 8 letters and digits is found nowhere). A node whose passage is let go stays, without a page.
- The request (`request`, `PROMPT`, `source`): the paper's details and its pages under `【第 N 页】`, up to `SOURCE` characters, and instructions that fix the outline's shape. A reply with no outline in it is an error to show, not an empty map.
- `layout` places the nodes: the root at the left, a node's children in a column to its right, the node in the middle of the height they take. How large a node is drawn is the window's to say (it measures the words), so it is passed in, as a fetching function is to `sources`.
- Kept in `mind_maps`, one JSON body a paper (`Store::mind_map`, `save_mind_map`), which goes with its paper. The tool `mind_map` reads it as its outline; no tool writes it yet (the window's sparkle is the only way a model's draft reaches a map, at the person's click).

## Screening (`screening.rs`)

Screening is against the library's goal (`LibraryInfo::criteria`, 筛选目标; empty means by the topic), saved as it is typed. Each suggestion keeps the goal it was made against (`screening_suggestions.criteria`, NULL for one from before, which counts as current; `Suggestion::made_for`); one made for another goal is shown as 按旧目标 and asked again by the next run. Each bulk run of the assistant (not `Cmd::ScreenAskOne`) calls `Store::begin_round(criteria, scope)`: a row of `screening_rounds` (made beside the library's tables, no version bump) with the goal, the scope (`pending`, `included` for 继续筛, `decided` for 复核) and the tally by status of the papers outside the trash, unless the latest row has the same goal (the same round going on). `screening::funnel(rounds, now)` makes the stages: `entered` by scope from the round's own counts, `included` the next round's included count (the last round's: `now`), so trashing or deleting papers later changes no finished round. Imports after a round began and rounds screened wholly by hand are not counted. 复核 (`Cmd::ScreenRecheck(false)`; with `true`, only the included papers) asks about the decided papers too: one the assistant now sees otherwise comes back to the queue (`Library::rechecking`, until the person decides it again, which keeps or changes the decision), the decision itself is never touched. Columns added later go through `store::add_columns`.

A suggestion never writes `papers.screening_status`: only the window does (确认 takes the decided papers back in the queue as well, `Library::confirmable`, so a round of 继续筛 is confirmed in one go; `Before` keeps what they were for 撤销), in `Cmd::ScreenDecide`, `Cmd::ConfirmApply` (the ticked suggestions written together, `Store::set_screenings`: one transaction, all or none) and the detail panel. An excerpt is kept only when `ai::locate_quote` finds it in the abstract or the full text.

The person's side of screening is `screening.rs`: `DECISIONS` and `status_of` (the keys: Y / R / U / N or 1 to 4, P or 0 for waiting again), `reason_for` (the reason kept with a decision: the assistant's when the person agrees, their own when the decision stays, none otherwise), `Round` (逐篇: the papers fixed when the round starts, the one on show, the decisions made so that the last can be taken back with what the paper was, `Before`) and `Confirming` (确认: the status chosen where it is not the suggested one, the papers left out, `plan` is what gets written; a suggestion made with nothing of the paper to read, `screening::unread`, `basis` `none`, is not ticked until the person ticks it or chooses a status, as the extract run does not ask about such a paper at all).

## A library in one file (`archive.rs`)

`.wispstudy` is a gzipped tar, written and read in `archive.rs` itself (ustar headers; a PAX record for a path over 100 bytes or not ASCII, or a file over 8 GiB; GNU long names read too), streamed both ways so a library of PDFs is never held in memory. The first entry is `wispstudy.json` (`Manifest`: `format`, which `FORMAT` bumps when an older build would misread an archive, and what is inside), so `peek` reads only the head; the rest is the folder under `library/`. The database goes as a `VACUUM INTO` snapshot, which is consistent while the app keeps it open; without attachments, `papers/` stays behind and the snapshot's `resources` rows are deleted, taking their text, sentences, structures, origins and PDF annotations with them (`ON DELETE CASCADE`). `removed/`, the journal files and downloads in progress never go. The export is written to `<name>.part` and renamed. `import` unpacks into a hidden `.importing-<id>` folder under the data root, skips any path that is not inside (`inside`) and the `._` forks a Mac's tar adds, opens the database once (a newer schema is refused, an older one brought up to date), writes `library.json` with a new id and a free name (`(2)`, `(3)`…) and only then renames the folder into place; on failure the hidden folder is removed. The tools are `export_library` (refuses to overwrite) and `import_library` (with `create_library`, not in `library_catalog`).

## Zotero's database (`zotero.rs`)

`zotero.rs` reads a `zotero.sqlite` of Zotero 6 / 7 read-only inside one read transaction (`snapshot`, which sees committed WAL data; never `immutable=1`), and every reader of it goes through `explained`, which tells a database Zotero holds (`is_locked`) from one that is no Zotero database. A database holds libraries (`libraries.type`: `user`, `group`, `feed`; `groups` names a group's library and has its id at zotero.org): `libraries` lists the person's own (`MY_LIBRARY`, 我的文库) and each group, with how many items `read` would take from it, counted by the same clause (`ITEMS`: no notes, attachments, annotations, feeds or what is in Zotero's trash). `read(path, library, collections)` reads one library by its `libraryID`, or all of them with `None`, narrowed to the items in the collections given (`collectionID`s) and their subcollections when there are any. `collections` lists every library's collections (`Collection`: id, library, parent, path `植物/根`, depth, and `items`, counted over the subtree with `ITEMS`; `members` keeps the item ids, unserialised, so `count_items` counts a choice of several without counting an item twice), in Zotero's order: each followed by what is under it, siblings by name (lower-cased code points, not Zotero's collation). A collection in Zotero 7's trash (`deletedCollections`, a table Zotero 6 lacks) is neither listed nor made a tag, and one whose parent is gone or that is its own ancestor is not listed (`Tree`). `choose_collections` turns names into ids: an id, a path (parts trimmed, any case), or a name only one collection has; none or several is an error that lists them. `under_picked` says whether a collection is taken in with a ticked ancestor. `choose` turns what a caller wrote into one of them (a `libraryID`, a group's id, a group's name in any case, 我的文库 / `user` / `My Library`; empty, 全部 or `all` is every library); a name that fits none, or two groups, is an error that lists the libraries there are. Tools: `import_zotero` (`zoteroLibrary`, through `choose`; `zoteroCollections`, through `choose_collections` over the collections of the library chosen; the result says which in `zoteroLibrary` / `zoteroCollections`) and `list_zotero_libraries` (the libraries and `collections`; read-only, no library of the app needed, handled before `find_library` in `call_with` and in `dispatch` for the window's assistant). `import_entry` takes one entry into a store, so one bad record or missing PDF does not stop the rest.

## A paper moved to another library (`transfer.rs`)

`Store::take_paper(from, id)` is 移到文献库: the target store takes the paper of `from` with what is keyed by it or its files there. The tables are copied as rows (`rows` / `put`: `SELECT *` by a key column, then `INSERT OR IGNORE` by column name with the paper's and files' ids changed), so a column added later goes along by itself; a new table keyed by `paper_id` or `resource_id` that belongs to the paper (not to a manuscript, a screening goal or a cache) must be added to the lists there. Files are copied first, each under a new `R-` id (`copy_hashed`, the record's title kept), and the rows keyed by a file go with its new id (`fulltext_text`, `structures`, `sentences`, `file_origins`, `reading_places`); marks (`pdf_annotations`, `pdf_shapes`, `pdf_cuts`), figures (their pictures copied to `figures/`), excerpts (methods and introductions) with their links to the figures the library now holds, the paper's conversations with their pictures, then one transaction. Custom fields go by name and kind (`Taken::fields_left` names the others). The screening decision is reset to pending: it was made against the other library's goal. A paper the target already holds (`existing_paper`, or the paper holding one of the files by `sha256`) is joined instead: blanks filled (`lookup::merge_lookup`), tags and notes added, the higher reading state and a star kept, a file it already has not copied again, marks already there (same id) not doubled. One in the target's trash refuses the move. The source keeps the paper in its trash; nothing is deleted. Not taken: screening suggestions, cite keys, passages, import batches (the other library's).

## A paper's files filed under another (`Store::file_into`)

归入已有文献: a supplement taken in on its own is a paper of its own; `Store::file_into(papers, target)` makes the files of those papers attachments of `target` and sends the records they came with to the trash, all of it in one transaction or nothing (a paper into itself, a record without a file, a paper that is not there or is in the trash: refused). A file keeps its id and its place on disk, so what is keyed by the file alone stays as it is (`fulltext_text`, `sentences`, `structures`, `ocr_pages`, `reading_places`, `file_origins`, `former_files`, and `paper_holding`, which now answers with the target). The tables that name the paper beside the file (`pdf_annotations`, `pdf_shapes`, `pdf_cuts`, `pdf_texts`, `figures`, `excerpts`) are handed over with it (`hand_file`): they refer to `papers` with `ON DELETE CASCADE`, so marks left with the old record would go when it is deleted for good. A new table that names both a paper and one of its files joins that list. A `fulltext` file becomes a `supplement` under the target; the other kinds stay.

What the record itself held (title, notes, tags, its conversations, its mind map) stays with the record in the trash. `filed_files` (the file, the record it came from, the kind it had there; made beside the first tables, no version bump) is the way back: `restore_paper` hands the files still there back to the record, as what they were, with the marks made since, and forgets the rows. So the trash is the undo, and the window's 撤销 is `restore_paper`. A row goes with its file (taken off the target, the target deleted for good) or with the record (deleted for good: the file stays the target's). A file filed on from the target keeps the first record it came from. `take_paper` does not copy the table: the record a file came from stays in this library's trash.

## 副表 (`table.rs`)

A paper's supplementary table is a file kept with it like any attachment (`Store::import_file` takes every format); `table` is what reads one, and the tool `read_table` what an agent reads it with. `open(path)` / `read(bytes, format)` give a `Book`: its `sheets` by name, and `sheet(n).rows(visit)` hands the rows over one by one under the number a spreadsheet gives them, without the empty cells at a row's end, passing over a row with nothing in it; `visit` answers whether to go on. Nothing holds a sheet whole, so a table of a hundred thousand rows costs its reading and no more (60 000 rows of seven columns: a quarter of a second in a debug build).

- `.xlsx` / `.xlsm`: the zip and XML readers of `docx` (`Zip`, `node`, `attr`), names without their prefix (`x:row`). The workbook part is the package's `officeDocument` relation, a sheet the `worksheet` relation its `r:id` names (a chart sheet has no rows and is left out; the strict ISO relation types end the same way). A cell is what a person reads in it: a shared string (runs joined, the Japanese reading `rPh` left out, `_x000D_` spelled), an inline string, a formula's last value, `TRUE` / `FALSE`, an error as written, a number to fifteen digits (`number`: 0.30000000000000004 is 0.3, 3.2E-120 is `3.2e-120`), and a date where the cell's style has a date format (`date_styles`: the built-in ids, or a format code of the workbook's own that names a day, month, year, hour or second outside quotes and brackets), counted from 1900 with its 29 February that never was, or from 1904 (`workbookPr date1904`). A cell or a row that does not say where it stands follows the one before.
- A workbook with a password and an `.xls` renamed are OLE files, not zip archives, and are told apart by their first bytes; `.xls`, `.xlsb`, `.ods` and `.numbers` are refused with the advice to save as `.xlsx` or `.csv`. Left out: number formats other than dates (a percentage is its fraction, a rounded figure the stored one), merged cells (the value is in the first), hidden sheets are read like any other.
- `.csv`, `.tsv`, `.tab`, and a `.txt` whose first lines hold tabs: `decoded` reads UTF-8, UTF-16 by its mark, GB18030 when every run of bytes above ASCII is of even length and decodes without a fault, Windows-1252 otherwise (a lone µ read as half a Chinese character would take the letter after it along). A `.csv` is cut at the comma, semicolon or tab its first lines hold most of. Commas: a quoted cell may hold the delimiter and line breaks. Tabs: a line is a row and a quotation mark counts only around a whole cell, since a gene's description may open with one that nothing closes.
- `header(first rows)` guesses which row names the columns: the first that fills three fifths of the widest row with cells of which at most half are numbers. A title in one cell above it is passed, a sheet of numbers has none.

`read_table` (`tools/local.rs`; `resourceId` of an attachment, or `path`; among `tools::ACROSS`) passes the whole sheet on every call, so `find` (a phrase in any cell, whatever its case) finds a row wherever it stands and `rowCount` / `matches` are those of the table. It hands back at most `rows` rows (50, 500 at most) from row `from`, fewer when their cells come to `BUDGET` bytes (a cell is cut at `CELL` characters), with `next` to go on from; `columns` keeps the columns named by the header or by their letters; `header` goes along whenever the rows read do not show it. The model learns of a table two ways: `RULES` names the tool, and for a paper being read `Context::add_tables` lists its table attachments with their ids after the documents (their rows are not handed over as a PDF attachment's pages are).

## The trash (`store.rs`)

A trashed paper is only marked (`trashed_papers`). Leaving the trash is for good, one paper (彻底删除, `purge_trashed`, which refuses a paper that is not in the trash) or all of them (清空回收站, `empty_trash`); both end in `purge`: the rows go in one transaction (`delete_rows`: the paper's row with what refers to it, and its conversations), then the files and pictures are unlinked from disk, each only when it lies inside the library folder and no remaining `resources` or `figures` row names it. `delete_paper` takes the same rows and moves the files to `removed/` (`set_aside`); it is what an undone import uses, never the trash. A file that cannot be unlinked is left and does not fail the call.

## 提取 (`extract.rs`)

提取 (`extract.rs`): a model's proposals for the custom fields. `FieldDef::hint` (a column added by `add_columns`) is what a field is said to be for, which the model is told; `extract::SUMMARY` (要点) is an ordinary Text field the window offers to add. `extract::prompt` asks about several fields of one paper in one request (the paper as `ai::paper_to_read` gives it, shared with screening) and `parse` reads the reply by field number or name; `coerce` brings an answer into the field's shape (a Select answer becomes one of its options or stays as said, which `fits` then refuses: a new option is never written) and the excerpt is kept only when `ai::locate_quote` finds it. One proposal per paper and field is kept in `field_proposals` (made beside the library's own tables, no version bump) with the definition it was asked under (`asked_as`); where it stands is read off the paper, not stored (`standing`: open, held by the field, silent, dismissed, stale), so a written value keeps the sentence behind it and taking a writing back makes its proposals wait again. `wanted` is which fields a run asks about for a paper (empty ones not asked about under the present definition; again when only the abstract was read and the full text is stored now). The person's side is `Reviewing` (ticked by rule: a value the field can hold, for an empty field, with a sentence behind it) and `taken` (a multi-value field keeps what it has). Only `Store::set_fields` writes `paper_fields` for this, one transaction, all or none; the tool `suggest_field` (in `WRITING`, not `CONFIRMING`) saves a proposal and refuses a Select value that is not an option.

## Models, providers and proxies (`provider.rs`, `imagegen.rs`, `judge.rs`)

Models per task: `Settings::providers` holds any number of model services (`provider::Provider`: address, key, proxy, protocol, and the `Preset` it started from), each offering any number of `provider::Model`s with an `id` (given by `Settings::tidy` / `add_provider` / `add_model`, unique across providers, never reused while in use) and its own `effort` (`ai::EFFORTS`: empty sends nothing, `off`, or a level). A model may also say how many tokens it takes in (`Model::context`, one of `provider::CONTEXTS` from its menu; 0 leaves it to `compact::window`), which is when a conversation with it is compacted. A new settings file starts with DeepSeek, Kimi and GLM (`provider::DEFAULT_PRESETS`); DeepSeek's smaller model comes first, since a task without a model of its own takes the first that can answer, and `Settings::tidy` puts a DeepSeek list still in the older order (`deepseek-v4-pro` first, nothing added) into the new one, ids and bindings untouched; each preset has its own key variable (`DEEPSEEK_API_KEY` …), so one service's key never goes to another. OpenCode Go (`opencode-go`) is one key for three interfaces, each at its own address (`provider::opencode_go_base`; the settings page moves the address when the interface changes), all known by `provider::is_opencode_go` (`opencode.ai/inference/go/…`, and the older `zen/go/…`; its pay-as-you-go `zen/v1` is not it), and its key variable `OPENCODE_API_KEY` holds on every interface. It refuses a request without `x-opencode-session` (HTTP 400): `ai::chat_request_with` adds one id per run of the app, with a `user-agent`, on all three protocols; requests built elsewhere (`imagegen`, `judge`) do not, since Go neither draws nor judges. What a request is made with is still the flat `ai::Profile` (`Provider::profile`, `Settings::profile` / `profiles`). `Settings::tasks` binds `Task::Chat`, `Screen`, `Translate` and `Structure` (写作's groundwork) to a model id; `Settings::profile_for` falls back to the chat model, then the first that can answer, then the first. A file from before providers keeps `profiles`, which `Settings::load` turns into providers (`migrate`: profiles with one address, key and proxy become one provider, their ids kept) and never writes again. `ai::apply_effort` is the one place that knows how each protocol, model and service spells thinking; a new service's way of turning it off goes there. Thinking a chat-completions service streams as `reasoning_content` (DeepSeek, Kimi, GLM) is kept by `TurnReader` and goes back in the turn's message: DeepSeek refuses a request with tools whose earlier turns lack it (HTTP 400). A conversation rebuilt from its text (`replay`) has none to send.

生图 (`imagegen.rs`): a provider's model either answers in words or draws (`provider::Model::kind`, `imagegen::KIND`; `Model::draws`). A name that says so makes a model added a drawing one (`imagegen::looks_like`, in `Settings::add_model`), the model's menu on 设置 › AI › 模型 changes it (`Settings::set_model_kind`), and presets bring theirs (`Preset::images`: OpenAI's gpt-image, the `gemini` preset, `ark` for 火山方舟's Seedream). OpenAI and Gemini also bring a model that answers in words (`Preset::models`), so a service added from them serves 助手 too (#206); 火山方舟 names its chat models per account and brings none. A preset seeds a provider only when it is added (`Provider::from_preset`): a service already in `settings.json` keeps the models it has. `Preset::example` is the name the add-a-model box suggests: a model that answers in words, a judge only for a service that has nothing else (TypeSafe). `Task::Image` is bound only to a drawing model and the other tasks never to one (`Settings::tidy`); `Settings::profiles` lists the models that answer in words, `image_profiles` those that draw, and `profile_for(Task::Image)` is `None` while no model draws: it borrows nothing (`Task::WORDS` are the other four). A drawing model is asked through one of three interfaces (`imagegen::Interface`, chosen in `Model::interface` or guessed by `imagegen::guess`): OpenAI's Images API (`{base}/images/generations`, also Seedream and most relays), Gemini's own `generateContent` (at Google's address; from a base ending in `/openai` or `/v1` the root is worked out), or chat completions that answer with a picture (a Gemini model behind a relay). `imagegen::request` builds the request (sizes and parameters per model family go there), `imagegen::read` finds the picture in the answer (bytes, or an address to fetch), `wisp_net::generate_image` sends it and returns a PNG, JPEG or WebP. A new service's way of asking for a picture is an arm in those two functions.

判断 (`judge.rs`): the third kind of model (`judge::KIND`, `Model::judges`; `Model::speaks` is one that answers in words), after TypeSafe's System One models (Jev): given a state and questions whose answers are fixed beforehand, it answers each with one of them and a probability for every one, and writes nothing. The `typesafe` preset brings `jev-latest` (`Preset::judges`), a name beginning `jev` makes a model added one (`judge::looks_like`), and the model's menu says its kind (`Cmd::SetModelKind`, `Settings::set_model_kind`). `Task::takes` is the one place that says which kind of model does which task: only `Task::Screen` takes a judging model, and only when the person chose it (`profile_for` never falls back to one); 提取, which shares screening's model, asks `Settings::speaking_profile_for`. In a screening run (`screen_next`) such a model is asked with `judge::screen_request` (one `choice` question, include / related / irrelevant, about the record and abstract, or the first pages without one; `POST {base}/systemone`) through `wisp_net::judge`, and `judge::read_screening` makes the `Judgement`: the verdict with the highest probability, 证据不足 when its confidence is under `SURE_ENOUGH`, the probabilities as the reason, no excerpt. Errors come as `detail` (`ai::error_message`). A new use of such a model is a question built with `judge::request` and a reader for its answer.

连接测试 (设置 › AI › 模型): `ai::test_request` is the one question a model that answers in words is asked (`TEST_QUESTION`, through `plain_request`, so the profile's thinking goes along: a setting the service refuses is one of the things a test finds), `ai::test_reply` the first line of what it said; `judge::test_request` / `read_test` are a choice between two answers for a model that judges. `wisp_net::test_model` sends either once, with no retry and a minute at most (`TEST_TIMED_OUT`), and reads the whole answer: a 2xx that carries no stream of an answer and no reason for stopping is something else at that address (`NOT_A_MODEL`, with the first of what came back). `ai::error_message` names 402 (DeepSeek's empty account).

Proxies: `Settings::proxy` is global and applied with `wisp_net::set_proxy` (app start, 设置 › 网络, and `wisp`); `Profile::proxy` overrides it for one model service (`direct` = none) and travels in `HttpRequest::proxy`. Empty everywhere means ureq reads the environment. `settings::proxy_problem` is the address check; `settings::proxy_address` is the address as kept and used (one written without a scheme, `127.0.0.1:7890`, is an HTTP proxy; a scheme's name alone is an address half typed and refused). What is handed to `set_proxy` is `Settings::global_proxy`: empty while `Settings::proxy_off` (the switch of 设置 › 网络, `"proxyOff"`) or while the address cannot be one. `settings::env_proxy` names the variable ureq would take, in ureq's order, for the page to say what is in use. `wisp_net::try_reach` is that page's test: one request through the global proxy, any answer counts.

## 朗读 (`speech.rs`)

Not a model: DeepSeek's speech service (`POST {host}/v1/tools/tts`, `speech::endpoint` takes the host's root whatever path chat has), with the key of the provider `Settings::speech_provider` picks (preset `deepseek` or an address at deepseek.com, one with a key first). `speech::request` asks for `format: pcm` (16-bit mono, 24 kHz) in `Settings::speech_voice` (`speech::VOICES`, `stella` / `tide`) with `filter_markdown` off. What is read: `speech::from_pages(pages, first, paper)` from a 1-based page on, each page as `page_texts` makes it and cut by `pieces` at sentence ends into `PIECE` (in `billed`: the service counts a Chinese character twice); it stops at a reference list's heading (`references_heading`). `page_texts` (also what `speech::body` joins for a podcast) splits a page into its blocks (the lines between blank ones, `page_blocks`) and leaves out the lines that come back on a quarter of the pages (`structure::furniture`: running heads and feet), page numbers and counts (`page_number`: `7`, `Page 2 of 17`, `2 / 22`, `第 3 页`), words set letter by letter (`without_spaced_letters`: `R E S E A R C H`), bullets, blocks without a word of two letters (Crossmark's `a1111111111`) and the labelled fields of PLOS's sidebar on any page (`FIELDS`); a heading standing alone gets a full stop when what follows on its page starts a sentence (`ended_headings`, so it is heard and marked apart). The first page goes through `first_page`: front matter is dropped (`front_matter`: `structure::is_notice`, the masthead's words, labels such as `EDITED BY` / `CITATION` with the block after them, lines that start as small print does (`Received`, `TYPE`, `*Correspondence`, `†`), e-mail addresses, affiliations (an institution's word and no verb), the journal's name as the record has it or as a running head has it, keywords); the record's title is found among the blocks (`same_title`, compared `bare`) and read first with the names after it (`authors`, without their marks of affiliation, `unmarked`), and of what stood before the title only what follows an `Abstract` heading is kept (BMC's layout of 2024 has the title under the abstract). Then `readable` joins the lines (a word hyphenated at a line's end made whole, bracketed citation numbers and web addresses left out). Tested on the page text of BMC, Frontiers and PLOS papers; `cargo run -p wisp_core --example structure -- a.pdf aloud "<title>" "<journal>"` prints what a PDF gives, a sentence a line. `sentences` cuts a text after each sentence end (what `pieces` packs): not at a full stop before a word all in small letters (`Lam. or`; `scRNA-seq` may open a sentence), after an initial (`O. R.`, `A. thaliana`) or an abbreviation (`structure::ABBREVIATIONS`, `NAME_ABBREVIATIONS`: botanical authors and ranks, months, titles), nor at a semicolon inside brackets (`(Denyer et al., 2019; Ryu et al., 2019)`), and `sentence_at` says which is heard at a share of a piece's sound, each sentence taking time by its length; `fulltext::find_spoken` finds such a sentence among a page's glyphs although reading left out its citation numbers and addresses: its first words without the bracketed (`bracketed_numbers`) and raised numbers, then its last words (24, 12 or 6 characters) not far after, the full stop after them included. `speech::Pcm` turns the bytes as they arrive into samples, keeping a sample split between two reads. `wisp_net::speak` sends a request and hands the sound to a callback as it streams (retrying a busy service before sound comes, like `post_json`; both go through `post_retrying`). The mock model answers such a request with a tone and prints the first 160 characters of the text it was sent.

## 播客 (`podcast.rs`)

Two hosts, 小星 (女, voice `stella`) and 阿潮 (男, `tide`), talk a paper over (`podcast::HOSTS`). The assistant's model (`speaking_profile_for(Task::Chat)`) is given `podcast::source`: title, authors, journal and year, abstract and `speech::body` (the readable text of all pages up to the reference list) cut at `SOURCE` characters, and told `PROMPT` (the language is the interface's: 中文 or 英文): 30 to 50 turns, each line beginning `女：` or `男：`, only what the paper says, written for the ear. `podcast::Reader` reads the script as it streams in: a turn is whole once the next marked line begins (also `**男**:`, `小星：`, `女主持：`, and `**Stella**:` / `**Tide**:`, the names of `HOSTS_EN`); an unmarked line goes on the turn before it, text before the first marked line is dropped, and bracketed stage directions and emphasis marks are taken out (`spoken`). `podcast::script` does the same for a whole text and errs (`NO_SCRIPT`) when no line is marked. Each turn is cut by `speech::pieces` and asked for in its host's voice (`podcast::pieces`), with `PAUSE` (0.35 s) of silence between speakers. What is kept: `podcast::wav` (a 44-byte header round the PCM bytes), `podcast::transcript` (Markdown, a turn a paragraph under the host's name) and `podcast::file_name` (「播客 - 题目」, without characters a file system refuses). Both take the interface's language: kept under the English interface the script is headed `# Podcast: …` with the hosts as Stella and Tide, and the files are named `Podcast - <title>`; the window draws the hosts by those names there too (`t` of `HOSTS`). `podcast::kept` tells those attachments apart (sound or script) for the playlist, under either name (`Podcast` only as `file_name` writes it, before ` - ` or the ending), and `script` reads either script back. Played again, `pcm_of` takes the PCM after the WAV's `data` header and `timings` shares the sound among the script's turns by their length after the pauses between speakers, as the sound keeps no marks.

## 期刊分区与影响因子 (`journals.rs`)

`data/journals.tsv` is compiled in (`include_str!`) and read once (`journals::table`, a `OnceLock`): one row per journal, the editions in `journals::EDITIONS` (JCR 2025, 中科院分区表升级版 2025, 新锐期刊分区表 2026, 国际期刊预警名单 2025) joined by ISSN, then by name. It is made by `data/journals.py` from the CSVs of [ShowJCR](https://github.com/hitfyd/ShowJCR) (`中科院分区表及JCR原始数据文件/`); a new edition is a change of the file names at the top of the script, a run of it, and of `EDITIONS` / the `*_YEAR` constants. The table is never edited by hand.

A paper keeps only its journal's name, so `Table::find` goes by name: the `key` (lower case, `&` as and, no leading "the") as it is, then as an abbreviation (`Nat Commun`, `J. Biol. Chem.`, `Proc Natl Acad Sci U S A`): the words without the small ones (`SMALL`) under their initials, each a subsequence of the full word with the same first letter (`shortens`). Two words at least, and only one journal may fit (one whose every word is a prefix wins over the others); otherwise nothing is guessed. A name PubMed wrote with more than the title is looked for as it is and then without that (`plain`): the subtitle after ` : ` (`The Plant journal : for cell and molecular biology`) and the place in brackets at the end (`Advanced science (Weinheim, Baden-Wurttemberg, Germany)`, `Adv Sci (Weinh)`). `by_issn` is for a caller that has one (`journal_metrics`). Sorting by `impact` and by a partition (`cas`, `xr`, `jcr`; `Journal::zone_rank`, Top before the rest of its zone) is in `filter::compare`; papers of unknown journals sink.


Translation: `ai::translate_request` (instructions from `Settings::translation_prompt`, else `ai::TRANSLATION_PROMPT`), kept in the library's `translations` table under `store::translation_key` (text and instructions), so a text is requested once. The window translates the selected paper's title and abstract while `Library::show_translation` is on.

Full text (#178, 对照译文): `translation::passages` takes the glyphs of every page (`pdftext::file_marks`) and gives what is translated, each `Passage` with its page, the box it stands in and its size: the paragraphs of `pdftext::page_paragraphs` (the lines between two of `page_text`'s breaks, which `breaks` now decides for both, so a paragraph that runs on in the next column or page is two) without the list of references (until a part of the paper begins again), what comes back on three pages or more, the words standing in figures (`wordy`) and short lines that are neither a part's name nor set apart over a paragraph. Each is a text of its own under the same `translation_key`, run as a `Batch::texts` (`Field::Body`, counted in paragraphs), so every paragraph is kept as it comes back, a run stopped halfway goes on from what is kept, and nothing kept is asked for again. `translation::fit` is the size a translation is set in to stand in its paragraph's box: the largest, up to the paragraph's own, at which its lines (`lines`, counted as the window breaks them: anywhere in Chinese, never inside a run of letters, digits and the marks that hold a word together, the text's own line breaks kept) are no higher than the box. The length over the width is not enough: in a narrow box (the type, date and DOI at the head of a journal's first page) a DOI goes to the next line whole and the last line was cut off. `cargo run -p wisp_core --example structure -- a.pdf passages` prints them, one line per request.

Batch translation: the marked papers' menu has separate title and abstract actions. `translation::Batch` snapshots and groups the selected texts, counts progress in papers, and skips empty fields; `src/translate.rs` shares cache and in-flight requests with the detail panel and keeps `Settings::translate_workers` batch requests in flight (`Batch::take` / `working`, answers settle in any order; 设置 › AI › 任务, default 4). `translation_next` drives either of a library's two runs (`translate::Run`: the marked papers', and the paragraphs of the paper read). Stop sends nothing more and keeps the answers already asked for; retry reuses successes. A per-open-library `Arc` rejects late answers after closing/reopening. Debug steps `key:ctrl-a,translate:titles` / `translate:abstracts` exercise the marked selection; `translate:stop` stops it.

Filtering by them (`filter.rs`, #236): `Filters::impact` is a span of the journal's factor (`5-`, `-3`, `5-10`; `impact_span`), `Filters::zone` a partition and the last zone kept (`cas:2`, `jcr:1`; `zone_parts`, `Journal::zone_number`, where Q1 is 1). `Filters::year` reads the same spans, a year alone, and `last:N`: the N calendar years up to this one and anything dated later (`year_span`, `time::year_of`). A value that says no span keeps no paper, and a paper without the number (no year, a journal the table does not know) passes no filter on it. `list_papers` takes them as `yearFrom` / `yearTo`, `minImpact` and `zone`.

## 分栏 (`panes.rs`)

The reading area as columns on an eight-unit grid (#194): the arithmetic, which the window draws (`render_paper_area`, `Workspace::pane_frame`). A layout is a list of `Column`s, each a `Pane` (列表, 文献, 译文 of the paper next to it, at its left else at its right (`source`), as wide as that paper so the two are read at one scale, 对话) and its units, written `paper:4,translation:2,chat:2` (`write` / `parse`); `refusal` says in a sentence why columns are no layout (units not adding up to `UNITS`, more than `MAX_COLUMNS`, two lists or conversations, no paper, a translation not next to its paper, not as wide, or a second one of the same paper). `PRESETS` are the layouts offered (阅读 8, 提问 2·3·3, 对照译文 4·4, 两篇对照 4·4, 精读 3·3·2, 两篇对照带译文 2·2·2·2). `arrange` gives each column its `Placement` in a window of a width: its own pane (`Shown`, left edge and width), inside another pane (`Inside`), floating over one (`Over`), or not drawn (`Away`). Panes share the width by their units, none below `Pane::min_width` (the window's own limits for the list beside a paper asked about, the PDF and the conversation) while there is room for all; where there is not, panes give way one step at a time (`give_way`): the list is put away; all translations go under their originals at once; the conversation floats over the first paper; the last paper is put away with its translation (the window says how many are, and shows one in the last pane it has room for; a paper is never squeezed into half of another's pane, where neither is read). A translation that goes into its paper's pane brings its units with it (the pane that holds both keeps the width of both, so the conversation beside them is no wider for it). A paper's least width is the one its pages are still read at beside another (440: three side by side in a window 1360 wide). Columns only, never rows (docs/dev/design.md, 面是连续的). `needs` is the width at which nothing gives way. A `Mode` (阅读, 对照译文, 提问, 精读) is a way of reading whatever papers are on show: `columns(mode, papers)` repeats each paper's columns as they are with one paper (with its translation in the two that translate), so 提问 is 2·3·3 with one paper and 2·3·3·3 with two: a paper beside another is given what it has alone, and the list and the conversation are what have a smaller share; with one paper a mode's columns are the preset of its key. `frame` is what a window gives the list and the conversation around several papers: the list the width it is kept at while every pane beside it keeps its least width (less while it keeps its own), put away first; the conversation its share of what the list leaves (not under 360 while the papers can spare it), or the width it was dragged to, never so wide that a paper beside it could not be read; the papers the rest, which `arrange` lays out among themselves. `grid` names columns by their units when they are on the grid of 8 (`3·3·2`), which is with one paper. Widths are whole pixels and fill the width to the last one.

## Organising and the manuscript tools (`organise.rs`)

Organising (`organise.rs`, tool `organise_papers`): tags added or removed, the star, the reading status and a paragraph added to the notes (marked as the assistant's, never replacing what is there), for any number of papers in one call, written in one transaction (`Store::organise`) or not at all. `organise::apply` changes a paper in memory and says in words what it changed, and nothing where the paper already is as asked; `Store::organise_plan` is the same without writing, which `organise::preview` (`tools::preview_call`) turns into a line per paper for the consent card (`PreparedCall::details`). Every call's arguments are read as the tool's schema means them before a tool sees them (`tools::fitted`, in `call_with` and `call_in_with`, and in `compose::call_with` before the citations are looked at): a list, an object, a number or a yes a model wrote as a string is what the string says, each item of a list too, and an empty string where anything but words is read is nothing given; any other value stays as it is, and what a tool makes of it is the tool's to say (a bare word for `queries` is still refused by the tool). A parameter a tool does not have is said with the ones it has. A file written elsewhere becomes one through `import_manuscript` (`tools/local.rs`; in `WRITING` and `CONFIRMING`, `preview_manuscript` is the card's lines): the same reading as 写作's own 导入 (`from_word` / `from_markdown`, `Store::import_manuscript`, then `retire_blank_manuscripts`), a Word file without heading styles cut at the likely guesses and said so (`guessedHeadings`; the person recuts in 写作), and a file that already is a listed manuscript not taken in again (`ManuscriptFile::already`: a Word file by the bytes of the copy kept, any other by its name while no word was changed, the addresses of its pictures left out of the comparison, `manuscript::without_addresses`). The path may be a folder (`manuscript_in`: the one `.docx` / `.md` in it or, with none there, in the folders right under it; a readme and a file whose name starts with `.` or `~` are none; several are named in the error for the caller to choose). A Markdown file brings its pictures (below). Citations stay the file's text. `restyle::note` tells the assistant of it with an attached Word file. Those two are in `CONFIRMING`: the window's assistant asks before each (`compose::preview` is the card's lines), except in the conversation that writes that very manuscript (写作's 助手写), where the pen was handed over. An answer also goes into a manuscript by the person's hand: 插入到稿件 under an answer of the library's conversation (`MenuKind::InsertInto`, the sections of the manuscript on the writing page; `Workspace::insert_into_section`) adds it, or what is selected in it, at the end of a section with `Store::append_to_section`, which keeps the section's text as a snapshot first and the citation keys with their papers; `cite::convert_ai_citations` makes the citations the manuscript's.

## Conversations started on the home page (`libraries.rs`)

A conversation started from the home page is a library with `LibraryInfo::draft` set (not written while false, so a library's `library.json` is as before): `libraries::create_draft` names it after its first question (`draft_title`, `DRAFT_TITLE_CHARS`), `promote` names it, gives it a topic and colour and clears the flag; nothing is copied or moved. `libraries::list` returns drafts with the rest; `shelved` leaves them out. The rule for agents is in `tools.rs`: `list_libraries` lists only the shelved, `find_library` counts only those for the library that may be left out and finds a draft by its id alone, and `sync_searches` without a library runs the shelved only. The database schema is untouched; an older build lists a draft as a library. `proposal_prompt` / `parse_proposal` are the model's proposal of a name and topic. `comment_manuscript` (in `WRITING`, not in `CONFIRMING`: a comment changes no word) leaves the assistant's remarks on a section as comments (`Store::add_remarks`, `origin` assistant); each quotation goes through `comment::remarks_in`, the same reading as a window review's `parse_review`, so a remark whose words the section does not hold is not kept and is returned in `missed`.

`offer_action` (`offer.rs`; neither `writes` nor `confirm`: it does nothing) is a card the assistant puts under its answer: a sentence and one to three buttons, each of the fixed `offer::KINDS` (`reply` with the words it says for the person, `promote_library`, `find_pdfs`, `open_page` with one of `offer::PAGES`). `offer::parse` refuses any other kind, so a model can offer only what the window knows how to run, and only the person's press runs it. Outside the window there is no card: the result tells the caller to say the options in words. `ai::draft_instructions` asks for one with 建成文献库 once papers came in.

## Conversations

Conversations are kept per library, under what they are about (`conversations.paper_id`: empty for the library's, a paper's id, or a manuscript's id for the conversation that writes it; `Library::talk_about`): `conversations` holds an `ai::Transcript` (what was said, and the sources it names) as JSON, `conversation_images` the pictures. `Transcript::of` decides which sources are kept: those an answer cites, those whose label stands bare in a question, an answer or a tool's line (`bare_labels`: models write 「P70 里」 and `**P32**` as well as `[P70]`, and a person asks about 「P24」), and every paper read in another library, which nothing but the transcript can name again under its label. The rest of the library's own papers are labelled anew when the conversation is taken up. What the model read is not kept: a conversation reopened from the history builds its context anew, and `ai::build_context` takes the transcript's sources as `known` so the labels in old answers still name the same papers. `ConversationInfo` is a row of the history: with `paper_id` and, for a paper's, its title (`about`), and as `title` the name the person gave it (`conversations.name`, a column added by `add_columns`; `rename_conversation`, whitespace collapsed, empty gives the first question back) or else the first question `save_conversation` keeps in `title`, never touching the name. `list_all_conversations` is 历史's 全部对话: the library's and those of papers not in the trash. `conversations_saying(words)` is its search: the ids of the conversations that hold every word (`LIKE` per word, `%` and `_` escaped, Latin letters in any case) in their title or name, their paper's title, or the text of a question or answer of the body (`json_each` over `$.items`, kinds `user` and `answer`; what a tool brought back is left out), so no body is read into memory. `time::ago` is the day a time falls on counted back from a given now (今天 / 昨天 / 近 7 天 / 更早), the headings of 历史.

`compact.rs` is the pure half of compacting a conversation, written after mangopi-cli's context manager and tested on all three protocols' wires: `tokens` / `text_tokens` (the estimate: three Latin letters or one Chinese character to a token, a picture a flat number, a signature nothing; measured against Claude and GPT counts), `window` / `limit`, `turn_starts` (a turn begins at a question; tool results and `LAST_STEP_NOTE` travel as the user's on some protocols and begin none), `trim_results` (a tool result over 800 tokens becomes its first 400 and last 200 characters, ending in `TRIMMED` so it is not cut twice), `make_room` / `tighten` / `drop_turns` (the layers, see `docs/dev/app.md`), `summary_prompt` (the record from `Said` items: a slash command as what it stood for, long answers clipped to fit `room`, an earlier summary first), `read_summary`, `summary_messages` (the summary as a user message and an acknowledgement, so turns still alternate) and `context_exceeded` (the services' words for a request too long). `Transcript::compacted` is optional and skipped when empty: a build from before it reads the conversation and sends it whole.

`usage.rs` is what a request used. `Usage` is the service's own count, read off the stream by `ai::TurnReader` on all three protocols (Claude: `message_start` and `message_delta`; chat completions: the `usage` of the last chunk, beside the choices or inside one; Responses: `response.completed`), with what was read from the service's cache where it says (`cache_read_input_tokens`, `prompt_cache_hit_tokens`, `prompt_tokens_details.cached_tokens`). For DeepSeek, whose API documents these: `deepseek_cost` prices a request in US dollars from `DEEPSEEK_PRICES` (the listed peak prices per million tokens of cache hit, cache miss and output; off-peak is half, `deepseek_peak`: 01:00 to 04:00 and 06:00 to 10:00 UTC on weekdays, Chinese public holidays not known and so counted as weekdays), `balance_request` / `read_balance` are `GET /user/balance` and its answer. The prices are a table to keep up by hand, dated in its comment: a model not in it gets no estimate, and a new model or price is a row there.


`mention.rs` is the pure half of @ in the question boxes: `tokens` reads `[@Key]` and `[@kind:value]` out of a text (`kind:` a lower-case word; a key like `doe:2020` whose kind is not in `KINDS` is tried whole as a key, `Keys::paper`), `typed` finds the `@` being typed before the caret, `short_name` / `byline` say a paper briefly (through `model::author_names`), `Keys` holds every paper's citation key from `cite::Index`, `matching` / `matching_libraries` are the popup's search, and `resolve` + `note` are what the model gets: each token written as `[P12]（Zhang 等 2024）` or 文献库「X」, and a Chinese note naming each thing once (a paper's label, title, authors, year, journal, DOI, abstract cut to 800 characters, whether its full text is stored and that `read_fulltext` reads it; a library's name, id, size, topic and that the tools take it as `library`), ending in that naming changes nothing and consents to nothing. `without` takes the tokens out of what `ai::reply_language` counts as the person's words; `readable` writes them as `@Key`, `#tag`, `§` where the library is not at hand (`Transcript::title`; the window saves its own with short names through `Transcript::title_by` and `Conversation::title`). Tags and sections: `token` percent-encodes what a value cannot hold (blanks, brackets, `;`, `,`, `@`, `%`) and `decode` reads it back, so `[@tag:root%20hairs]` carries any name; `matching_tags` / `matching_sections` and the ranked `matching_ranked` / `matching_libraries_ranked` feed one flat popup, `share` gives each kind with rows at least `FLOOR` of `OFFERED`; `Thing::Tag` is written 标签「X」（N 篇） and noted with its first ten papers by label and short name and `list_papers` with `tag` for the rest, `Thing::Section` 稿件「T」的「节名」一节 with the manuscript's title and id, the section's id and kind, its length and its text up to 1500 characters (else `read_manuscript` with both ids), and a line that naming a section is no request to change it.
Figures: `[@figure:<paper>/<file>/<number>]` (`FIGURE`, `figure_value` / `figure_named`; the number is `key_code` of a `figref::Key`, `fig3`, `figS2`, `figE1`, `table2`, `scheme1`, read back by `key_of_code`, said `Fig. 3` by `key_written` where the paper's own words are not at hand, as `readable` does). `matching_figures` takes a number typed loosely (`fig3`, `Fig. 3`, `figure 3b`, `图3`, `tab2`, `表2`, `figs2` for Fig. S2, through `figref::key_of`) or the start of a kind (`fig`, `表`) at rank 0, words of the caption at rank 1. `FigureSeen` is what the window found (paper label, attachment number, page, number as written, caption, the picture's place among the question's pictures or why there is none); `Thing::Figure` is written `[P1 p.5] 的 Fig. 3` (`[P1 S1 p.2]` in an attachment, `FigureSeen::cited`) and noted with its place, its caption up to `LEGEND_MAX` and that its picture is the n-th attached, or that none could be cut and why. `figure_picture_id` is a stable hash of the value: one picture per figure, whatever is asked again. A paper's part of the note says a question beyond the abstract is answered only after `read_fulltext` / `search_fulltext`, and that without a stored full text the answer rests on record and abstract (issue 301).
Methods and introductions: `[@excerpt:<id>]` (`EXCERPT`, one kind for both; `readable` writes `¶`). `matching_excerpts` looks through the name, tags, words and notes (rank 0 a name, or without one the start of the words, that begins with the query); `excerpt_label` is the folded `方法·名字` / `Method · name`, `excerpt_side` the row's `Zhang 等 2024 · p.5`. `Thing::Excerpt` is written 方法「名字」 / 导言「名字」 and noted (`excerpt_note`) with its id, where it is from as answers cite (`[P3 p.5]`, `[P3 S1 p.5]` in an attachment, `[P3]` without a page; or that the person wrote it down, or that its paper is gone), the passage whole up to `EXCERPT_TEXT_MAX` (2000) characters, else its start and `list_methods` / `list_introductions` with `id`, a line that these are the source paper's words to learn from and not to copy unquoted (not for one the person wrote), the notes said to be the person's, the tags, and for a method the linked figures (number, gallery id, page, caption cut short) with `list_figures` to look at them. `share` gives every kind with rows one row first, then up to `FLOOR` in order, then the rest: with five or six kinds the last ones have one and none is left out.

## Full text, structure and languages (`pdftext.rs`, `structure.rs`)

Full text for writing (`pdftext.rs`, `structure.rs`): `fulltext::file_pages` reads a PDF with hayro's interpreter first (`pdftext::pages`: glyphs with position, size and weight become lines, and a blank line marks every break the page shows, so a heading stands alone; raised citation numbers are left out, ligatures spelled out) and falls back to pdf-extract, which panics on about a third of publisher PDFs. `structure::blocks` turns the page text into paragraphs and headings, `assign_sure` gives each paragraph its part by rule (a heading that names a part, `canonical`; without an "Introduction" the text before the paper's first own heading is the introduction; a review's own headings are `other`; an "Abstract" heading lasts `ABSTRACT_WIDTH` or until a heading of the paper's own, then the part it interrupted goes on) and says where it only guessed, `sentences` cuts the kept paragraphs. The words of a button the publisher draws on the page (Crossmark's "Check for updates", `is_button`) are passed over: standing alone they looked like a title and headed the sentences after them. `parse_outline` reads a model's answer about the outline; one that names no block because the file has no body text (`none`, or nothing at all, which is what "list only body text, explain nothing" comes to for a supplement) is `structure::NO_BODY`, said as it is and not counted towards the run giving up (`wisp_net::NO_CONTENT` is how the window tells that empty answer from a failure). A hyphen at a line's end is kept or dropped by the paper's own spelling (`Lexicon::keeps_hyphen`: the compound written elsewhere, the word written whole elsewhere, a gene or a number before it, a closed prefix, and in English two words the paper writes on their own); test a change on real lines both ways. `Store::save_fulltext_pages` does this for every text it keeps: `sentences` rows plus one `structures` row per file (`rules`, `model`, or `none` for a file without text; `open` counts the guessed paragraphs, `paragraphs` all of them, and `StructureInfo::worth_asking` / `structure::worth_asking` is the one place that decides whether a model's look is offered: many guessed, or a good share of a short piece).

Languages: lengths are counted in `structure::width` (a Chinese, Japanese or Korean letter counts three), sentences end at `。！？．` as well, a sentence or heading may open with a letter of a script without capitals, `canonical` knows the headings of Chinese, Japanese, Korean, German, French, Spanish, Portuguese and Italian papers, and `words` gives character pairs for CJK runs (Latin words keep the stemmer; `OTHER_STOP_WORDS` beside the English ones). Each text's language (`structure::language`, from the script and the commonest words of its kept body text, `body_language`) is the `structures.language` column, `StructureInfo::language`, and `Sentence::language` on every sentence `section_sentences` returns: that is the field to read when choosing sentences by language. The writing page's groundwork line counts the texts per language when there is more than one. In `pdftext`, a page's usual line spacing (`usual_leading`) keeps Chinese set with wide leading in paragraphs, and a numbered title set like the text (`numbered_title`) stands alone. A file without a `structures` row has not been through it: `tools::extract_missing` and `Workspace::extract_missing` read such files again, so libraries from before 写作 catch up on their own; bump `structure::VERSION` when the rules change and `restructure_outdated` redoes the rule-made ones. The abstract is never taken from the PDF: `find_sentences` reads it off the record.

## Finding words through a library (`find.rs`)

`find::in_library` is 全库查找's engine (#273), and `search_fulltext`'s for everything but its ranked full-text pages: the words looked for exactly (`fulltext::find_text`, the find bar's `bare` comparison over a text: no case, spaces, hyphens or line breaks, so a word broken at a line's end and a word inside a run of Chinese are found) in every paper's title, abstract and notes, every reading mark (`pdf_annotations`: the text marked, and apart from it what was written on it; a mark is one place however often the words come back in it) and the page text of every file (`Store::each_text`, a file at a time, the trash left out; `Texts::Attachments` leaves the full texts to the tool's own loop). Each `Hit` carries the paper, its `Place`, the file and page, the sentence the words stand in on one line with the words' range in it (`passage`: the text's own words, its spacing made one space, so the window can light it on the page as a citation's sentence is; a sentence shorter than `SHORTEST` takes the text round it, a long one is cut at a word and says so in `cut`), the words' range in the text itself (`at`, for the notes) and, for a mark, its kind, id, boxes and whether the words were written on it. `Found` keeps at most `per_paper` places of a paper but counts them all (`counts`, `total`), sorts the papers with most first, and says which papers' text was not looked through: `textless` (a full text that gave no text) and `unread` (not read yet), so "not found" is never read as "the library does not say it". `stop` is asked between files. Read only. `search_fulltext` keeps its old answer by default (one hit a page of the full texts: the whole phrase as `find_text` finds it, else the scattered words); `in: all` adds the engine's other places, each with a `kind`.

## A PDF made smaller (`shrink.rs`)

`shrink::shrink` writes a PDF anew with lopdf (the one pdf-extract reads with) and only its pictures changed (#242): an image longer than `LONGEST` (2400 px, about 200 dpi across A4) is scaled down with the `image` crate, a JPEG stays a JPEG at `QUALITY`, a lossless one becomes a JPEG only when that is at most half its lossless size (a photograph; drawings, charts and screenshots stay Flate), and a soft mask is scaled and kept Flate. Left alone: anything but gray or RGB (DeviceGray / DeviceRGB, ICCBased with 1 or 3 components, CalGray / CalRGB), other than 8 bits, a `Decode` array, a colour-key `Mask`, a stencil mask, a mask with `Matte` and its image, JPX, a TIFF predictor, and any image that would not come out a tenth smaller. Then the objects not reached from the trailer go (`unused`, a set walk: lopdf's own `prune_objects` is quadratic), the bare streams are packed, and the result is checked: lopdf finds the same page count and `pdftext::pages` the same text on every page, or nothing is kept. A PDF with `Encrypt` is refused, since lopdf would write it out unprotected. Images are worked on one a core. `Shrunk::worth` (a tenth smaller) decides whether the file is replaced; `Store::replace_file` puts the bytes in place under the same resource id (text, structures, marks, places stay), moves the original to `removed/` under a name not taken there, and keeps its hash in `former_files`, which `paper_holding`, `paper_holding_bytes` and `import_file` read with the current one (`HOLDING`), so the original dropped in again is this paper. The tool is `compress_pdf`; the window's button shows on a PDF of `shrink::HEAVY` (10 MiB) or more that is not in `Store::shrunk_files` or found not to get smaller in this window (`Library::no_smaller`), and every PDF's menu has 压缩 PDF. On a 95 MB Nature paper (extended-data figures at 5400 px, Flate) it gives 13 MB in about a second; a Cell paper whose weight is vector drawings gets 7% smaller and is left as it was. Try a file with `cargo run -p wisp_core --release --example shrink -- in.pdf [out.pdf | --largest]`.

## A PDF with its marks written in (`annotpdf.rs`)

`annotpdf::write(source, marks, target)` is 导出带标注的 PDF (#273): the file written anew with lopdf (as `shrink` does) and every mark of `annotation` that `exported` takes (all but `Kind::Cut`, a note to oneself) put after the page's own `/Annots` (inline or an array object of its own; links and earlier annotations stay) as a standard annotation: `/Highlight` and `/Underline` with one `/QuadPoints` quad per box in Acrobat's order (upper left, upper right, lower left, lower right of the box as shown), `/Square` with `/BS` for a box, `/Text` (`/Name /Comment`, a 20-point icon) for a note, `/FreeText` for a text box (`/DA` in its ink, `/Rotate` of the page when turned). Each has `/Contents` (the note or the words, a text string: plain when ASCII, else UTF-16BE behind its BOM; none for an empty note), `/C` (the colour the window draws: a highlight's at `Theme::highlight`'s 0.32 over white, so readers that draw their own multiply it as the app tints; a box's swatch; a text box's fill), `/NM` the mark's id, `/M` and `/CreationDate` from the mark's own times (so the same marks give the same bytes), `/F 4`, `/P`, and an appearance (`/AP /N`, a form whose `/BBox` is the `/Rect`) drawn as the window draws the mark: its content starts with a `cm` that turns the window's points into the PDF's space, so everything after is in the window's terms (a highlight's boxes filled under an `ExtGState` with `/BM /Multiply`, an underline 1.3 points at a box's foot, a text box's fill, edge and words). The hues are `annotation::hue` (which `theme.rs` reads too); a text box's three colours repeat `Theme::text_fill` / `text_border` / `text_ink` in RGB. Its words are wrapped here (`wrap`: each letter at the width of the font it is set in, an em in the CJK font, at `TEXT_PT` with `TEXT_LEADING`, broken at spaces or after any CJK letter), the box grown to hold them as `PdfView::grown` does, and set letter by letter (`set`) in fonts no file has to embed: Helvetica (WinAnsi, with its € • ™ “ ” – — at 0x80–0x9F), Symbol (Greek, arrows, the signs of mathematics) and ZapfDingbats (✓ ✗ ★ ● ①–⑩) for what they hold, and `STSong-Light` with `UniGB-UCS2-H` (a hex string of UCS-2 codes) for CJK script only (`cjk`: ideographs, CJK and full-width punctuation, kana). macOS's own renderer (Preview, Quick Look, `sips`) draws the CJK font's ideographs and full-width punctuation right but every other letter of GB2312 as an unrelated ideograph (→ as 於, Greek, ①, ℃, kana; `UniGB-UTF16-H` or another supplement changes nothing), so a letter no base font has is first taken apart (`nfkd` without its marks: ā → a, ₂ → 2, ℃ → °C) and only else left to the CJK font, which MuPDF and Acrobat draw. “ ” ‘ ’ — … go with the words they stand by (`shared`: an opening mark with the letter after it, the rest with the one before), full width among Chinese, narrow among Latin. Kana and the few letters no base font holds even taken apart (☆ ○ ł) still come out wrong on macOS. A letter beyond the BMP is left out of the drawing, never of `/Contents`. Checked with `sips -s format png` and PyMuPDF on a text box holding each kind (`letters_go_to_a_font_that_draws_them` keeps the routing). PDFKit (Preview) and MuPDF show the Chinese; hayro, and so the app itself, has no CJK font for a font left unembedded and draws only the Latin words (`InterpreterSettings::font_resolver` is where one would go). Where a page lies is hayro's own `Page::initial_transform(true)` inverted (`places`), the transform the marks were placed with: the crop box cut to the media box, its origin, `/MediaBox`, `/CropBox` and `/Rotate` inherited from the page tree, a quarter turn either way or upside down. `/UserUnit` scales the marks and the annotations alike and needs nothing. The page counts of lopdf and hayro must agree, else nothing is written; a mark of a page the file lacks is counted in `Marked::left`. A file with `/Encrypt` is refused (lopdf would write it unprotected), as is a target that is the source; the bytes go to `.<name>.part` beside the target and are renamed onto it. The tests build small PDFs with lopdf for each geometry (with quads worked out by hand from the standard) and check that a glyph hayro reads off a cropped page turned each way comes back onto the glyph. Not a tool yet: `export_pdf_annotations` would be a catalog entry and an arm reading `Store::pdf_annotations` of a file and calling `write` with an `output` that is never an existing file, as `make_slides` takes one.

## Candidate sentences (`retrieval.rs`)

Candidates: the tool `find_sentences` (part; `query` and/or `queries`; optional paper, `tag`, `starred`; `context` adds the sentence before and after from the same paper and part) ranks the sentences of one part (`retrieval.rs`): each query on its own with BM25 over `structure::words`, against a `retrieval::Index` that `index_for` keeps in memory by a hash of the part's texts (no stored word bags, so a change to `words` needs no migration), the lists merged by reciprocal rank fusion (`fuse`, then at most `PER_PAPER` per paper); without a query it returns how each paper opens the part. `tools::extract_missing` first asks `Store::structure_wanted` and returns at once when every file is sorted. The window and `/write` both go through it; `cargo run --release -p wisp_core --example retrieval_bench` times a search over 4000 made-up sentences.

## Open full texts and completing by title (`openaccess.rs`, `complete.rs`)

Open full texts (`openaccess.rs`, tool `find_pdf`): candidates for a paper come from its arXiv number, from OpenAlex and Europe PMC (asked by DOI or PMID, no key and no address of the asker), and, only when one of the two says the paper is open access, from the publisher's own address for the few publishers that hand a PDF to a plain client (`publisher_candidate`). Nothing logs in or goes round a wall; Europe PMC's own PDF rendering is left out because it answers browsers only. What comes back is kept only if it is a PDF (`is_pdf`) and not a paper's supplement (`openaccess::supplement`: every one of its first pages that says anything holds the caption of a supplementary figure or table or opens with a supplement's heading; a repository lists the supplement among a paper's files and an index hands it on as the PDF), with its origin in `file_origins`. The text is read before the file is stored (`fulltext::pdf_pages`), a supplement is said among the reasons and the next candidate is tried. Several reasons are one sentence through `sources::reasons` (each without its own full stop, so no 「HTTP 403。；」). The tools take a second function for this, `sources::Download`, beside `Fetch`. In the window it is a run like the import's (`Library::fetching`, `fetch_start` / `fetch_next`).

A pasted web address (`webpage.rs`, tool `import_url` in `tools/web.rs`) is fetched once, with the person's own network standing: on a campus the publisher lets in by its addresses, the PDF comes too. Still nothing logs in, keeps a cookie or passes for a browser (`wisp_net`'s own `USER_AGENT`), and of the page's links only the one it names as its PDF is followed. A PDF that comes back is taken in as a dropped one is (`take_pdf`: the DOI on its first pages looked up, the same bytes known by `Store::paper_holding_bytes`). A page is read for its scholarly meta tags (`webpage::meta`: `citation_pdf_url` made absolute against the page by `resolve`, `citation_doi` / `dc.identifier` / `prism.doi` when they hold a DOI, `citation_pmid`, `citation_arxiv_id`, title, authors, journal, year; either attribute order, either quote, entities read). With no number on the page, or no page at all (a 403, a check), the DOI written in the address is taken (`doi_in_address`: only a part that starts a path segment or a query value, without the view after it, `/full`, `.pdf`, a bioRxiv `v2`). The record comes from `lookup::find` (Crossref and Europe PMC through `Fetch`; `wisp_net::lookup_paper` is that function with `get_text`), the page's tags filling its blanks, or the page alone when no database knows the number (an arXiv DOI); `Store::import_papers` decides whether it is new. Its PDF is the page's own first (`fetch_pdf_from` with that address as the first candidate), then the open copies `find_pdf` would try. A record without a PDF stays, `pdfReason` saying why in one sentence; an address with neither a number nor a PDF adds nothing (`not_recognised`). One address takes two minutes at the most (`TIME_FOR_ADDRESS`), lookup and open copies included, so that a host holding a connection does not keep the addresses after it waiting. The limit is `sources::within`, a deadline of the thread the tool runs on: `wisp_net`'s `get_text` and `download` give a request no more than `sources::time_left` and wait 30 s instead of 120 for an answer to begin (`timed_agent`), a request cut by it says 「迟迟没有答完」 and not the timeout's own words (`cut_short`), and whoever goes on to a next request asks `sources::out_of_time` first, which puts `TIME_UP` among the reasons once. What came in by then stays (the record from the page's own tags when the databases were not reached); `find_pdf`, which sets no limit, is unchanged and is how the PDF is looked for again.

Completing by title (`complete.rs`, tool `find_metadata`, 按题目补全 in the detail panel for a paper with neither DOI nor PMID): `complete::find` asks Crossref, Europe PMC and arXiv for records by title (`PER_SOURCE` each), reports each source on its own (`Asked`: found, nothing, or why it failed), makes records of one DOI one `Candidate` and orders them by `similarity` (words in the same order; 1 only for the same title). The title asked for is the paper's, or, while that is the name of its file (`placeholder_title`), the one its first page shows (`pdftext::title_guess`), for the person to correct. Nothing is written by the tool or by a model: the window (`Modal::Complete`, `complete_find` / `complete_apply`) has the person pick a record and its fields; `complete::suggested` is what is ticked beforehand (blank fields, a title that is a file name) and only for a record at least `ALIKE_ENOUGH` like the title; a record the library holds as another paper is refused. There is no browser bridge and none is wanted: sources are asked over HTTP like every other lookup.

Completing by number (按 DOI 补全 / 按 PMID 补全, in the paper's right-click menu whenever it has either, and as a button in the detail panel while its journal, authors or year are blank): `complete::by_identifier` takes the one record `lookup::find` gives for the DOI (else the PMID) and makes it a `Candidate` compared with the paper itself (`same` starts with "DOI 一致"; title, year and first author as for a title search). A DOI read off a first page may be a cited paper's, so a record whose title is not the paper's has `similarity` under `ALIKE_ENOUGH` and nothing ticked; a title that is a file name is not compared. `Candidate::by` (题目, DOI, PMID) goes into the 来源 note `apply` writes. The window shares `Modal::Complete` with the title search (`CompleteForm::by_id`, `complete_lookup`): it asks as it opens, shows the record field by field, and has no list to go back to.

## Quotations

Quotations are checked: `ai::check_quote` looks a quotation up in the stored page text (`Quoted`: found, elsewhere, only its beginning, missing, no text), `Library::check_quotes` does it for the finished answers of a conversation, the chips say the result. `ai::citation_spans` is where an answer cites, for the clickable citations in the text.

## 文字识别 (`ocr.rs`)

`ocr_pdf` reads the pages of a PDF that gave no text (`fulltext::readable_by_eye`: a scan, a font without an encoding, a file the readers stumble over) or that a model read only in part. Each engine is a row of `ocr::ENGINES` (its key, name, key variable, where a key is had, the most pages and bytes it takes); one that takes the file itself also has an arm in `request` and `read`, and nothing else knows which engines there are. DeepSeek (`POST {host}/v1/tools/ocr`, a `multipart/form-data` body of `purpose` and `file` and nothing else, built by `ocr::form`; the chat API's key; 1000 pages and 100 MiB a file, three minutes in all, 15 at a time an account, billed by the page) answers with line breaks while it works and then one JSON document (`pages[].text`, `finish_reason: length` for a page it stopped in the middle of: `Page::cut`); a failure after it began comes with HTTP 200 and an `error` in the body, which `read` looks for first. The second engine, `model` (`ocr::MODEL`), is the model of `Task::Structure` looking at pictures of the pages, one page a request (`ai::read_page_request`): it has no arm in `request`, since the pages have to be drawn, which only the window does (`pdf::page_pictures`). `OcrSettings` (`Settings::ocr`) holds the engine (`AUTO`, empty, is the first that can be asked; `OFF` none) and the keys by engine; `ocr::ready` picks: a key stored for 文字识别, then the DeepSeek model service's with that service's proxy and host (`Ready::base`: so a relay, or `mock_model`, is asked where its key is for), then the engine's variable; the model engine is ready when the task's model lacks nothing.

What DeepSeek writes for a page is Markdown, as a run with a real key showed (`purpose: text_recognition`, the test `what_the_service_writes_becomes_the_text_of_a_page` holds its answer for a scan of two pages): a heading opens with `#`, a table is HTML (`<table border=1><tr><td>…`), and every figure with a unit is a formula (`$4\ ^\circ\text{C}$`, `$2.4$`); the columns of a page come in their order, and a paragraph the end of a column cuts in two comes as two. Left like that no heading names a part of the paper (`structure` sorted the methods under the introduction) and no sentence is found by its words, so `ocr::plain` makes the page's text of it: tables and formulas are set aside first (`tables`: the rows as lines, cells apart by ` | `; `formulas`: `$…$` on one line, `$$…$$`, `\(…\)`, `\[…\]`, two prices being no formula), a formula that says no more than figures, units and plain signs becomes those (`untex`: `4 °C`, `10⁻³`, `CO₂`; one that is built, a fraction or a raised letter, stays as written), paragraphs cut in two are joined while the Markdown still says what is a heading (`mended`: a long one that stops at a small letter or a comma before one that opens with a small letter or a figure; in Chinese, Japanese and Korean a letter before a letter), and `markdown::plain` takes the marks off. A new habit of the service is a case for that test.

The documentation also shows marks of place, `<｜ref｜>text<｜/ref｜><｜box｜>[[x1, y1, x2, y2]]<｜/box｜>` with the corners in thousandths of the page from its top left; the answer to `text_recognition` had none, so they are `rich_layout_recognition`'s, which has not been run yet. `ocr::pieces` reads them all the same (wide or plain bars, `det` as `box`, several boxes as the rectangle around them), `plain` leaves them out with a blank line between two placed pieces, and `blocks` gives the pieces with their places as fractions of the page: that is for a text layer over the page, which will have to ask for the other purpose. The text goes where any page text goes (`Store::save_read_pages`, `structures.text_by` naming the engine, sorted into parts by rule), and what the engine answered is kept as it came in `ocr_pages` (`Store::save_ocr_pages`, made beside the library's tables, taken along by `transfer`): recognition costs, the answer says more than the text made of it (which lines are headings, a table's cells, a formula), and a better `plain` can make the text again without asking twice.

The tool (`tools::ocr_pdf`, in `WRITING` and `CONFIRMING`: the file leaves the machine and the pages are billed) is lent its way out as `web_search` is (`Reach::read`, an `ocr::Read`: engine asked for, file name, bytes; `wisp_net::read_file` reads settings anew, refuses the model engine with a sentence, and `send_file` asks again only a service too busy to begin). It reads one attachment, a paper's, or every textless PDF of the library up to `limit`, leaves a file with text alone, and stops after `OCR_GIVE_UP` failures in a row. The one exception is a file named (by `resourceId` or `paperId`) whose pages were read off them and some came back empty (`ocr::blank_pages`: never a file that gave its own text, where an empty page is a figure, nor one read in part): only those pages are sent again, cut out by `ocr::only_pages` (lopdf; a file it cannot parse goes whole), and `ocr::refill` puts what came back in their places, a page still empty keeping what it had; the row says `retriedPages` / `filledPages`, and nothing is written when none was filled. The window does the same from the file card's 识别没有文字的 N 页 (`Cmd::ReadPages` of that file; the model engine draws those pages only, `pdf::page_pictures_at`); a run over the whole library never sends them again, which would bill the pages of figures with every run.

## Web search (`websearch.rs`)

`web_search` searches the web for what the literature databases do not hold. Each engine is a row of `websearch::ENGINES` (its key, name, key variable, most results, longest query, where a key is had) and an arm in `request` and `read`; nothing else knows which engines there are, so a new one is those three places. DeepSeek (`POST https://api.deepseek.com/v1/tools/search`, the chat API's key, a query of at most 128 characters, `summary` the longer text and the one kept) and Jina (`GET https://s.jina.ai/?q=…&num=…`, `X-Respond-With: no-content` unless the page text is asked for) and You.com (`POST https://ydc-index.io/v1/search`, the key in `X-API-Key`; `extraction_mode: highlights`, the free passages that speak to the query, make the summary, and with the page text asked for `full_page` brings the page as Markdown; `results.knowledge` is left out) are the three. `Hit` is the one shape every engine's answer is read into (title, address, summary, site, date, and the page's text cut at `CONTENT_CHARS`); an error is said with the engine's name, what the status means and the service's own words. `Settings::web_search` holds the engine (`AUTO`, empty, is the first with a key; `OFF` none) and the keys by engine; `websearch::ready` picks the engine and its key: one stored for web search, for DeepSeek then the DeepSeek model service's (with that service's proxy), then the engine's variable. Settings are read anew by `wisp_net::web_search` at every search, so a key typed in the window holds for `wisp` at once; requests that fail with 408, 429 or 5xx are sent again as `post_retrying`'s are. The window offers the tool to the assistant only while `ready` finds an engine (`chat_step`), so a person without a key is not shown a tool that cannot work; the command line and MCP list it always and say where a key goes.

What the network side lends the tools beyond `Fetch` and `Download` is `tools::Reach`: Notion (`publish`) and web search (`search`), `wisp_net::reach()` in the app and `wisp`. `Reach::default()` lends nothing, which is what tests and the plain `call` / `call_in` pass; a tool whose way out was not lent says so in a sentence.

## Search sources (`sources.rs`)

`sources.rs` searches PubMed, Europe PMC, Crossref and arXiv (PubMed and arXiv answer in XML, read by the small `elements` helper). A search asks for `PAGE` (200) records at a time and again for the next page, until it has what was asked for (`MAX_RESULTS`, 2000, at most) or the database has no more: PubMed gives all ids in one `esearch` and the records by `efetch` a page of ids at a time, Europe PMC pages by `cursorMark`, Crossref by `offset`, arXiv by `start` (`wisp_net::get_text` waits three seconds between two requests to arXiv). A page that fails after others came ends the search with those (`Found::stopped`): `run_search` imports them, keeps the reason in the batch's `error` beside its counts and returns it as `stopped`, and the search is due again within the hour like one that failed. A run after the first does not fetch it all again (`search_new` with `Known`, which `run_search` fills from the store). PubMed's ids come before its records, so a record whose PMID the library holds is never fetched (`Found::passed`, counted as retrieved and skipped). The others send whole pages: when the search's last run went through all it was asked for (`ImportBatch::depth`, the limit it had; 0 for a run that stopped short, and for all of a search's runs once one of its batches is undone) with the same query and no fewer records asked for, a page with nothing new ends the walk, unless the database's count has grown since by more records than were found, which means a new one stands further down (Crossref sorts by relevance, PubMed and Europe PMC by publication date, not by when a record came in) and is looked for through the whole depth. The guide saves its searches with `broad_limit`: the most for the databases sorted by date, one page for Crossref. A saved search is a `searches` row; each run is an `import_batches` row with its papers in `batch_papers`, which is what `undo_batch` takes back: untouched papers only (a decision, reading, star, notes, tags, fields, a file, a conversation about it, a citation in a manuscript or a place in the trash make a paper touched). They leave the library and not for its trash, where they would keep blocking the next run; their records are first set aside as `removed/undone-import-<batch>.bib` (`Undone::set_aside`), which imports like any reference file, so nothing is lost by an undo.

Who is asking (`sources::Contact`: an email and an NCBI key, both optional, from `Settings::contact`, which leaves out an address that could not be one and reads `NCBI_API_KEY` when no key is stored). The URLs core builds never hold it: `wisp_net::get_text` adds it to what it sends (`sources::identified`, by host: `tool`, `email` and `api_key` for NCBI's E-utilities, `mailto` for Crossref, which answers it from its faster pool, `email` for Europe PMC, nothing for any other address, so an email never goes to arXiv, OpenAlex or a publisher), and errors name the host, not the address asked. `wisp_net::set_contact` is called where `set_proxy` is: at the window's start, on a change in 设置 › 网络 › 文献数据库, and at the start of `wisp`. With a key the turns NCBI's requests take are 110 ms apart instead of 400 (`take_turn`). A database that keeps answering 429 is named with what would have it take more from this caller (`sources::more_allowed`: `GIVE_NCBI_KEY`, `GIVE_EMAIL`, sentences `i18n` has English for), and NCBI's 400 for a key it does not know is said as that. A new database that wants to know its caller is an arm in `sources::database` and one in `identified`.

## Tutorials (`tutorial.rs`)

The pages of `site/tutorials` and `site/en/tutorials` are built into the program (`PAGES`, `include_str!`), and read by a small HTML reader of its own (enough for pages written by hand: void elements, entities, closing tags that close what was left open inside them) into a `Shelf` (from `index.html`) and a `Tutorial` per page: head, numbered `Section`s of `Block`s (paragraphs, lists, quotes, screenshots, code, notes, tables; text as `markdown::Rich`, keys as code), colophon. What the window does not draw (the site's header, footer, language switch, table of contents and pager) is not read: the shelf gives the order, so 上一篇 / 下一篇 come from it. `link` says where an `href` leads (`Link::Page` for a page and section of the tutorials, `Link::Web` for anywhere else) and `resolve` makes a screenshot's address whole on the project page (`SITE`); `cached` is where it is kept, never outside the cache folder. A page added to the site is added to `PAGES`: `every_page_of_the_site_is_built_in` fails until it is, and `every_tutorial_reads_into_sections_and_its_links_lead_somewhere` reads every page in both languages and follows every link between them.
