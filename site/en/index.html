A local-first literature library

The papers are yours.
So is the judgment.

Wisp Study keeps your papers and PDFs on your computer. Import in bulk from a search query, let the assistant read every paper and give suggestions backed by quotes from the text, and confirm each one yourself. Then ask the library questions: a source in an answer opens the very page it came from.

Download See a complete run

macOS, Windows, Linux · MIT license · No account needed

Abstract. We started from an empty Wisp Study and built a library around “植物单细胞转录组” (plant single-cell transcriptomics). The assistant drafted 6 search queries Fig. 3c; we used 2 of them and imported 355 papers from PubMed and Europe PMC Fig. 3d. The assistant read all the abstracts in 4 minutes 40 seconds and gave its suggestions Fig. 2. After we confirmed them, 313 papers remained, and we asked one question about them Fig. 3h. The whole run took about 15 minutes. This page records that run, and why the tool is designed the way it is.

§1Case

A real run: fifteen minutes, from empty to 313 papers

The numbers and screenshots below come from a run on macOS on November 10, 2026. The topic was single-cell and single-nucleus transcriptome sequencing in plants. The databases change every day and the model answers differently each time, so your numbers will differ when you follow along. The steps are the same.

aSet up a model

Wisp Study does not come with a model. In “Settings › AI”, enter a model provider of your own: the Claude API, an OpenAI-compatible chat/completions endpoint, or OpenAI's Responses. There is no save button; changes are kept as you make them. The assistant, bulk screening and translation can each use a different model. This time translation went to a small model that does not think much.

bCreate a library

Besides a name, write down the topic: what the library collects and which questions it cares about. It is more than a note. The assistant reads it when it drafts queries, judges inclusion and answers questions, so it is worth being specific. Pick an accent color; from then on it is the library's highlight color.

cHave the assistant draft queries

The assistant drafted three differently aimed queries each for PubMed and Europe PMC, and tried each one out at once: how many papers the database returns, and what the newest few are. The broad query returned over a thousand papers, and its newest results were mixed with fracture healing. The methods query returned almost nothing but plant single-cell studies. Judge by the titles, not by how elegant the query looks.

dSave and import

Two queries were used, each fetching the latest 200 papers. The two databases overlapped by 45 papers; after deduplicating by DOI, PMID and title, 355 papers remained, all “Pending”. This is deliberate: import broadly first, then judge paper by paper. If an import was a mistake, every batch can be undone as a whole.

eHave the assistant screen

Write the screening goal: what kind of papers belong in this library and what kind do not. The assistant reads 8 papers at a time. It reads the full text when there is a PDF; here there were only abstracts. Each paper gets a suggestion, a reason, and one sentence quoted word for word from the text as evidence. You can stop partway, and the papers not yet read wait for the next round.

fConfirm the inclusion decisions

The assistant never changes a paper's inclusion decision. Only you do. Open a paper, look at its reason and evidence, then accept the suggestion or choose another. Once you have looked at a few papers in a group and trust it, you can accept the whole group; it asks first.

gRead translated abstracts

“Show translation” next to the abstract swaps the title and abstract for the translation in place, and “Show original” switches back. Once it is on, other papers you switch to are translated automatically. Translations are saved in the library, so the same text is requested only once.

hAsk the library

Ask in “Assistant” on the left. The scope is the 313 papers in the current list: 181 were given as full records, and the 132 that did not fit were given as titles only. The assistant first used its tools to read 5 papers that compare the two technical routes directly, then answered. It also wrote that these papers have no PDF saved, so this time it cites no page numbers: it read only the abstracts.

How would you judge this one?

On the right is a real suggestion from that run. The screening goal was: include plant studies that actually produced or analyzed single-cell or single-nucleus transcriptome data. This paper does single-cell proteomics.

The button the assistant suggests is filled in. Click it to accept; or choose another.

§2Ideas

Why it is designed this way

Seven rules we follow ourselves. After each one we say where it lands in the product, so you can check.

  1. 01

    The papers are yours

    No account, no cloud. Each library is a folder under “Documents/WispStudy”, holding the database, the PDFs and the custom fields. You can back it up on its own, or copy the whole folder elsewhere and keep using it.

    In the productAttachments are recorded as paths relative to the library folder. What leaves your machine, and who it goes to, is listed item by item in Data and privacy (in Chinese).

  2. 02

    The assistant proposes, a person decides

    The assistant reads fast, but whether a paper is included is your judgment. It gives a suggestion, a reason and a confidence, and never changes any paper's inclusion status. It also asks first before a whole group is accepted.

    In the productAn external agent connected through the command line or MCP can only make suggestions (suggest_screening). No tool can overwrite an inclusion decision.

  3. 03

    Say it with a source, and let the source be opened

    A screening reason must carry one sentence quoted word for word from the abstract or full text; what cannot be quoted does not count as evidence. A [P3 p.5] in an answer opens that paper's PDF at that page, with the quoted sentence highlighted on the page. When it cannot be found, it says so.

    In the productWithout a PDF the assistant can read only the abstract. It says it read only the abstract, and does not make up page numbers.

  4. 04

    Take in broadly first, read closely after

    Rather than write a very narrow query at the start and worry about missing something, import broadly in bulk, deduplicate, and let the assistant go through the papers one by one, leaving you the few dozen worth reading yourself. We call this broad intake.

    In the productEach import is a batch and can be undone as a whole; papers you have already handled are kept. A saved query can run by itself every 6 hours, daily or weekly.

  5. 05

    Nothing is really lost

    Removing a library or an attachment only moves it to removed/. Deleted papers go to the Trash and can be restored.

    In the productPapers in the Trash stay in the library and keep blocking the same paper from being imported again: what you judged unwanted does not come back with the next sync.

  6. 06

    Native, not a web page

    The whole interface is drawn on the GPU by Rust and GPUI, with no WebView and no Electron. PDFs are rendered by the pure-Rust hayro, with no dependence on a system PDF library.

    In the productLight and dark interfaces, an accent color per library, and every shortcut can be changed.

  7. 07

    One table of tools, three ways in

    The assistant in the window, the command line and MCP use the same table of tools. A rule is written in one place, so whichever way you come in, what can and cannot be done is the same.

    In the productSee the next section.

Limits for now

  • It is early, and it changes fast.
  • The assistant features need a model provider of your own; the API key is saved in plain text in settings.json on your machine.
  • Each run of a query fetches at most the latest 2000 papers; this run was made on a version where the limit was still 200.
  • The Linux version does not update itself; it only tells you a new version exists.
  • The Linux version is not signed and has not been tested on a real machine.
§3Tools

Beyond the window: wisp and MCP

wisp is the way in without a window, and it ships with the installer. It reads and writes the same data folder as the app, and works while the app is open. Each tool is both a subcommand and an MCP tool, and the output is JSON.

Table 1. Tools at a glance. Those marked write change the library; wisp mcp --read-only does not offer them.
list_librariesThe ID, name, topic and paper count of every library
library_statusAn overview of one library: the count for each status, and the custom fields
list_papersSearch, filter and page through papers, with the same rules as the list in the window
get_paperOne paper's full record, fields and attachments
search_fulltextFind a phrase in the saved full texts; returns page numbers and verbatim snippets
read_fulltextRead the full text by page, at most 8 pages at a time
find_citationsFor a piece of text, find sentence by sentence the papers in the library that may support it
search_onlineTry a search query on PubMed, Europe PMC, Crossref or arXiv without writing anything
list_searchesSaved search queries
save_searchwriteSave a search query
remove_searchwriteDelete a search query
run_searchwriteRun and import, skipping papers already there; returns the batch number
list_importsImport records
undo_importwriteUndo an import as a whole batch; papers already handled are kept
sync_searcheswriteRun the queries that are due
suggest_screeningwritePropose an inclusion suggestion for one paper; it does not change the inclusion decision, which you confirm on the Screening page

§4Download

Download Wisp Study

The latest version is on the release page.

macOS

macOS 11 or later, Apple silicon or Intel

Apple silicon Intel

WispStudy-vversion-macos-arm64.dmg

WispStudy-vversion-macos-x64.dmg

Signed with a Developer ID and notarized by Apple. After opening it, drag Wisp Study into “Applications” and run it. If you are not sure which one you have: in the Apple menu › About This Mac, a chip named Apple M… is Apple silicon, and one named Intel is Intel.

Windows

Windows 10 / 11, x64

Installer Portable

WispStudy-vversion-windows-x64-setup.exe

WispStudy-vversion-windows-x64.zip

The installer installs for the current user, needs no administrator rights, and adds an entry to the Start menu. The portable version runs WispStudy.exe after unzipping and does not write to the registry. Both are Authenticode-signed and both update themselves.

Linux

x64

Download from the release page

WispStudy-vversion-linux-x64.tar.gz

After unpacking, run wisp-study. It is not signed and has not been tested on a real machine.

After installing

  • The command-line tool wisp ships in the package: on Windows and Linux it sits next to the main program (for the installer, in %LOCALAPPDATA%\Programs\Wisp Study), and on macOS it is at Wisp Study.app/Contents/MacOS/wisp.
  • Collecting, organizing, PDFs and export need no model. Asking questions, the library wizard, screening and translation need a model provider of your own, set up in “Settings › AI”.
  • SHA256SUMS on the release page holds the checksum of each file.
